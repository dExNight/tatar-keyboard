# EMOJI-SUGGEST, миссия 4: полевые дефекты (M4a/M4b/M4c)

Дата: 2026-09-02. Основание: `docs/EMOJI-SUGGEST-PLAN.md` (миссия 4). Все три
дефекта воспроизведены на эмуляторе (tt_suggest_a14, debug APK 1.9.10) ДО фикса,
затем проверены ПОСЛЕ. Свидетельства — `docs/emoji-suggest/evidence/m4*.png`.

## M4a. «этэч» не находит 🐓 — пробелы tt-покрытия поиска эмодзи

**Симптом**: поиск эмодзи по-татарски «этэч» пуст.

**Корень (подтверждён аудитом)**: tt-ключевые слова поиска писались вручную
(`scripts/emoji_search_tt_extra.txt`, 200 эмодзи из m2) — 🐓 туда не попал.
Аудит всей панели (`emoji_set_v1.txt`, 1389 последовательностей) против
tt-ассета: покрыто 200, без tt-слов — 1189.

**Фикс**: курируемое расширение `emoji_search_tt_extra.txt` до 1318 эмодзи
(+1118 строк): полностью секции животных, еды, эмоций, жестов/тела, плюс
частотные объекты, транспорт, погода, символы, флаги. Пропущены 71 редкая
позиция (записано): диагональные/поворотные стрелки (10), зодиаки (13),
кейкапы цифр (11), японские/китайские знаки-кнопки (18), служебные кнопки
ввода (🔠🔡🔣™, ➰➿〰️✖️⚧️🔱⚜️, часть 🈯/🈁) и три понятия без надёжного
однословного tt-эквивалента: 🦇 летучая мышь, 🦤 дронт, 🦗 сверчок.
Сомнительные слова сверялись с корпусом OpenSubtitles-v2024.tt
(үрмәкүч, күсе, буа, сула, калак, көрәш, оекбаш и др. подтверждены).
Пересборка `emoji_search_v1.txt` (`emoji_search_pack.py build --tt-extra`):
216 426 Б (guardrail 262 144), 1389 строк, tt-покрытие 1318/1389.

Позитивный контроль: «этэч»/«әтәч» → 🐓 (python `tests/emoji_search_pack`,
JVM `EmojiSearchTest` + эмулятор: `m4a-search-etach.png` — запрос «этэч»
даёт 🐓 первым результатом).

**Синхронизация suggest**: аудит `emoji_suggest_data.tsv` нашёл 191 эмодзи
с ru-строками без tt. Дописано 151 tt-строка (номинатив по понятию);
18 позиций осознанно пропущены — слово уже занято другим эмодзи
(ат/балык/кар/торт/йомырка/сәгать и т.п., включая denylist-конфликты) —
дубль слова в suggest запрещён fail-closed («одно слово — один эмодзи»).
Ассет пересобран: 3976 записей (ru 2501 + tt 1475), zlib 17 285 Б
(budget 32 768), пины пересчитаны в `tests/emoji_suggest_pack` и
`EmojiSuggestIndexTest`.

## M4b. Татарские слова не дают эмодзи-подсказку

**Репродукция** (debug 1.9.10, префы через run-as):
- тоггл выкл (дефолт): «йөрәк » → полоса [өянәге · авыруыннан · белән], ❤️ нет
  (`m4b-toggle-off-no-emoji.png`);
- тоггл вкл: «йөрәк » → [өянәге · авыруыннан · ❤️] (`m4b-toggle-on-heart.png`).

**Корень (подтверждён)**: фича исправна; дело в тоггле
`PREF_EMOJI_SUGGESTIONS` — opt-in, по умолчанию OFF, и его никто не находил
(подозрение (1) из плана). Триггер «слово+пробел» и подчинение
мастер-тогглу подсказок работают как задумано.

**Фикс (решение по коду)**: дефолт ON. Альтернатива — одноразовый диалог
по образцу SuggestionsOfferController — отвергнута: фича пассивна (лишняя
ячейка в полосе, не меняет ввод), уже подчинена мастер-тогглу подсказок
(он сам opt-in с оффером 1.3.0), второй модальный диалог за «вкусовую»
мелочь — перебор; смена дефолта — две строки + контракт-тест. Явно
выключившие пользователи не затрагиваются (преф пишется только при касании
переключателя). Дрейф дефолтов читателя и экрана настроек страхует
`EmojiSuggestDefaultSourceContractTest`.

После: префы содержат только мастер-тоггл → «йөрәк » сразу даёт ❤️
(`m4b-after-default-on.png`).

**Конфузиблы** (подозрение (3)): добавлены курируемые алиасы в
`emoji_suggest_data.tsv` — «йорэк» → ❤️, «жыр» → 🎵 (частотные слова с
ө/ә/җ, набранные русскими о/э/ж). Автоматическое порождение алиасов
отвергнуто: полисемия («сою» = доение vs сөю, «ой», «тон») недопустима
без вычитки; список пополняется вручную. Эмулятор: «йорэк » → ❤️
(`m4b-after-confusible-jorek.png`).

## M4c. Полоса поиска эмодзи переживает скрытие клавиатуры

**Симптом**: поиск «кот» → home → вернуться в поле — полоса поиска с
результатами висит, но ввод идёт в редактор (полоса мертва).

**Корень (подтверждён репродукцией, `m4c-before-*.png`)**:
`LatinIME.onWindowHidden` не сбрасывал поиск — `abandonEmojiSearch()`
вызывался только из onFinishInputViewInternal (он роняет запрос, но не
флаги), а `KeyboardSwitcher.mEmojiSearchShown` и видимость
`EmojiSearchView` переживали скрытие. При следующем показе полоса видна,
но `mEmojiSearchQuery == null` → `maybeRouteToEmojiSearch` молчит → буквы
уходят в поле («йөрәк м» на скрине — «м» набрана в редактор поверх живой
на вид полосы «кот»).

**Фикс**: в `onWindowHidden` — `abandonEmojiSearch()` +
`mKeyboardSwitcher.hideEmojiPanel()` (обе no-op, если панель не открывалась).
Пересоздание вью (`onCreateInputView`) флаги уже сбрасывало — проверено
контрактом. Выбранное поведение: поиск закрывается при скрытии (сброс,
предсказуемо). JVM-контракт `EmojiSearchHideResetSourceContractTest`.

После (`m4c-after-reopen.png`): home → возврат → обычная клавиатура с
полосой подсказок, поисковой полосы нет.
