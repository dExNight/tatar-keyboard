## Метод

1. Кандидаты — пересечение ключевых слов CLDR из `emoji_search_v1.txt` со
   словами частотных словарей проекта (`dictionary_pack.validate_asset`,
   top-20 000 каждого): ru — 1 692 точных хита, tt — 558. Сырые хиты CLDR
   непригодны напрямую («можно»→🚬, «работа»→😫, «нет»→😑, «день»→🥳),
   поэтому дальше — только ручное курирование.
2. Курирование по категориям: эмоции (сущ. + глаголы), приветствия/жесты,
   животные, еда, природа/погода, праздники, спорт, семья/люди, транспорт,
   дом/предметы/техника, цвета. Правило отбора: понятие очевидное
   («солнце»→☀️), без натяжек; сомнительное не входит.
3. Словоформы выписаны вручную (никакой алгоритмической флексии):
   ru — падежи ед.ч. (мн.ч. — где частотно: «глаза» не входит, «дети» входит),
   ё/е-варианты («самолёт»/«самолет»), глаголы — инфинитив + настоящее время;
   tt — основа + аффиксы -ны/-не, -га/-гә/-ка/-кә, -да/-дә/-та/-тә,
   -дан/-дән, -лар/-нәр, плюс частотные формы глаголов (-ыйм/-им, -ый, -ыйлар).
4. Валидация fail-closed в пакере: каждое слово проходит
   `dictionary_coverage.normalize_word` с алфавитом своего языка; каждый
   эмодзи обязан быть в `emoji_set_v1.txt` (панель умеет его рисовать); одно
   слово → ровно один эмодзи на язык (конфликт фатален); дубли строк фатальны;
   denylist полисемии фатален. Гардианы: ≤ 131 072 байт raw, ≤ 32 768 байт
   zlib-9, 2 000 ≤ строк ≤ 8 192.
5. Формат ассета: `язык<TAB>слово<TAB>эмодзи`, сортировка (язык, слово),
   UTF-8/LF, детерминированная сборка.

## Границы

- en не входит (план: «опционально»; tt — приоритет ЦА, ru+tt достаточно
  для 1.9.10).
- Одно слово → один эмодзи на язык; одно понятие может иметь несколько слов
  («солнце»/«лето» → ☀️) и один эмодзи — несколько понятий.
- Фразы («туган көн», «день рождения») невозможны по контракту слова
  (normalize_word не пропускает пробелы).
