# EMOJI-SUGGEST-PLAN — план реализации эмодзи-подсказок в полосе

Дата: 2026-09-01. Основание: `docs/EMOJI-SUGGEST-RESEARCH.md` (вердикт: вариант A,
курируемые данные, append, отдельный тоггл). База: main с 1.9.9.

**Зафиксированный дизайн (из ресерча):**
- Триггер: слово набрано целиком и завершено разделителем (пробел/знак) →
  эмодзи появляется в NEXT_WORD-полосе рядом с биграммными предсказаниями.
- Тап = append через существующий `commitPredictedWord` (ничего не удаляется,
  пробел добавляется). Replace-семантика запрещена.
- Эмодзи-источник дополняет ячейки с конца (паттерн companion-fill) и никогда
  не вытесняет словарные/биграммные кандидаты.
- Отдельный тоггл в настройках (по умолчанию — решить при реализации: проект
  традиционно opt-in для подсказок).
- Данные: курируемый ассет `emoji_suggest_v1.txt` со словоформами, ru+tt
  (en — опционально, CLDR готов; решается в миссии 1).
- Никаких попапов/звуков/хаптики при показе.

## Миссия 1. Данные: курируемый ассет emoji_suggest

**ГОТОВО КОГДА:** ассет собран конвейером, запинен, покрыт тестами, прошёл
глазную вычитку; размер ≤ 32 КБ сжатого.

1. `scripts/emoji_suggest_pack.py` (stdlib, fail-closed, как остальные пакеры):
   - вход: курируемый TSV `scripts/emoji_suggest_data.tsv` — `эмодзи TAB язык TAB
     слово TAB словоформы через запятую`;
   - источник понятий: пересечение CLDR-keywords с top-N нашими словарями
     (частотность решает, что курируется), фильтрация полисемии вручную;
   - выход `app/src/main/assets/emoji/emoji_suggest_v1.txt` + пины (SHA-256,
     число записей) + NOTICE;
   - гардианы: размер, число записей, каждый эмодзи существует в emoji_set_v1,
     каждое слово tt/ru проходит normalize_word соответствующего алфавита.
2. Курирование: ~300–800 понятий. Русский: формы существительных (6 падежей),
   глаголов (ключевые), прилагательных — по шаблонам, с вычиткой. Татарский:
   агглютинативные формы (основа + частотные аффиксы: -ны/-не, -га/-гә, -да/-дә,
   -дан/-дән, -нар/-нәр…), опора на существующий `scripts/emoji_search_tt_extra.txt`.
   Denylist полисемии: «кит», «бар», «ключ», «можно», «работа», «день» и т.п.
   (список из замеров ресерча — стартовая точка).
3. Тесты `tests/emoji_suggest_pack/`: формат, гардианы, denylist работает,
   детерминизм сборки, все эмодзи из набора панели.
4. Глазная вычитка: выборка ≥50 случайных + весь denylist — протокол в отчёт.
5. Отчёт `docs/emoji-suggest/DATA.md` + evidence (выборка скринами не нужна —
   данных).

## Миссия 2. Движок: читатель + seam в контроллере

**ВЫПОЛНЕНА 2026-09-01.** Отчёт: `docs/emoji-suggest/ENGINE.md`. Уточнение
приоритета ячеек (датированная пометка, текст риска ниже не переписан):
«свободная/крайняя ячейка» прочитана как «крайняя» — эмодзи закреплён за
хвостовой ячейкой, биграммы занимают передние (не больше двух при наличии
маппинга), companion-слова вставляются перед эмодзи; иначе фича не показывалась
бы никогда — все контрольные слова оказались головами биграмм с ≥3 преемниками
(замер в ENGINE.md).

**ГОТОВО КОГДА:** эмодзи появляется в полосе на завершённом слове, не вытесняет
предсказания, тап вставляет; всё под тестами.

1. Читатель `EmojiSuggestIndex` (Android-free, fail-closed): HashMap слово→эмодзи
   при парсинге; ленивая загрузка на фоне (по образцу EmojiSearchIndex); ноль
   аллокаций на запрос.
2. Seam в `SuggestionsController`: на NEXT_WORD-контексте (слово + пробел)
   эмодзи-кандидат дополняет ячейки с конца, после биграммных; сессионная
   привязка и stale-защиты — как у companion-fill.
3. Вставка — существующий `commitPredictedWord`; ничего нового в InputLogic.
4. A11y: contentDescription = имя эмодзи (через EmojiSearchIndex.resultNameAt).
5. Тоггл в настройках (`SettingsHostActivity`, строки на трёх языках, гейт
   вместе с подсказками).
6. JVM-тесты (~25–35): seam-логика (не вытесняет, порядок, stale), читатель,
   гейты приватности (пароль → нет эмодзи), тоггл.
7. Эмулятор: набрать «самолет » → ✈️ в полосе; tt «йөрәк » → ❤️; скриншоты.
8. Отчёт `docs/emoji-suggest/ENGINE.md`.

## Миссия 4 (2026-09-02). Полевые дефекты от оператора

**ВЫПОЛНЕНА 2026-09-02.** Отчёт: `docs/emoji-suggest/FIXES.md`. Кратко:
M4a — tt-покрытие поиска доведено с 200 до 1318/1389 (позитивный контроль
«этэч»→🐓), suggest пополнен 151 tt-строкой (1475 tt-записей); M4b — корнем
был opt-in дефолт тоггла, решение: дефолт ON (подчинение мастер-тогглу
сохранено), конфузиблы «йорэк»/«жыр» добавлены курируемыми алиасами;
M4c — поиск сбрасывается в `LatinIME.onWindowHidden`, мёртвая полоса ушла.
Эмуляторные до/после — `docs/emoji-suggest/evidence/m4*.png`. Гейты зелёные
(JVM 1069, python 346, lintRelease, no-internet, release 1 820 351 Б).
Версия/CHANGELOG — отдельный релизный шаг (по плану 1.9.12).

Три проблемы, найденные оператором на живом использовании. Корни предварительно
локализованы чтением кода — в миссии подтвердить эмуляторным воспроизведением
до фикса (правило проекта: сначала репродукция, потом правка).

### M4a. «этэч» (🐓) не находится поиском эмодзи

Корень: у 🐓 нет tt-ключевых слов вообще — `scripts/emoji_search_tt_extra.txt`
(200 ручных синонимов из m2) покрыл 🐔 (тавык), но не 🐓. Класс: пробелы покрытия
tt-ассета поиска, а не одно слово.
**Фикс**: аудит покрытия — сверить emoji_set с tt-ассетом, дописать недостающие
tt-синонимы для частотных понятий (животные/быт: этэч, дуга?..), пересборка
поискового ассета + пины + тест (позитивный контроль «этэч»→🐓).

### M4b. Татарские слова не дают эмодзи в полосе подсказок

Данные есть («йөрәк» и формы в `emoji_suggest_data.tsv`). Подозрения по коду:
(1) тоггл `PREF_EMOJI_SUGGESTIONS` — **opt-in, по умолчанию выключен**: оператор
мог просто не включить; (2) триггер — только слово+разделитель; (3) частая опечатка
«йорэк» (русские о/э вместо ө/ә) маппинга не имеет — вопрос алиасов-конфузиблов
(ә↔э, ө↔о, ү↔у, җ↔ж, ң↔н, һ↔х) решить осознанно: либо алиасы в данных, либо
задокументированный отказ.
**Фикс**: эмуляторное воспроизведение с включённым тогглом; если фича работает —
закрыть пробел обнаруживаемости (первый показ-предложение, как у подсказок в 1.3.0,
или состояние по умолчанию — продуктовое решение с числами); конфузиблы — по решению.

### M4c. Полоса поиска эмодзи переживает скрытие клавиатуры и дохнет

Корень (по коду): `EmojiPanelController.onFinishInputView()` (строки 307–310) гасит
отложенный показ и пишет реценты, но **не сбрасывает состояние поиска** — полоса
поиска остаётся видимой при следующем открытии с мёртвой сессией (неинтерактивна).
**Фикс**: сброс поискового состояния на onFinishInputView/пересоздание вью;
JVM-тест (panel state), эмуляторный сценарий «открыть поиск → набрать → скрыть →
открыть» до/после.

## Риски и границы

- **False positives** — убиваются только курированием; метрика приёмки миссии 1
  — ноль срабатываний на контрольном списке из 100 частотных слов-ловушек
  (составить в миссии 1 из замеров ресерча).
- **Конкуренция за ячейку**: на NEXT_WORD-полосе эмодзи может отобрать третью
  ячейку у биграмм — порядок: биграммы впереди, эмодзи только в свободную/крайнюю.
- **Вариант B** (эмодзи под курсором без пробела) сознательно отложен: трогает
  замороженный текстовый контракт; оценить спрос после 1.9.10.
- Бюджет: ассет ≤ 32 КБ + код; APK должен остаться ≤ ~1,81 МБ (запас огромный).
