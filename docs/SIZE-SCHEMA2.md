# SIZE-SCHEMA2 — словари TATDICT schema 2 (front-coding + varint-частоты)

2026-09-01, миссия SIZE-1 кампании ужатия APK (ресерч: `SIZE-OPTIMIZATION-RESEARCH.md`).
Lossless: состав, порядок и частоты словарей побайтно те же; поменялась только
упаковка. Читатель schema 1 удалён — весь код работает на schema 2.

## Формат (schema_id = 2, format_version = 1)

Заголовок — те же 72 байта, что у schema 1 (magic `TATDICT\0`, SHA-256 с занулённым
полем на смещении 40), поля @20..@36 переосмыслены:

| Смещение | Поле |
|---|---|
| 16 | entry_count (u32) |
| 20 | block_count (u32) = ⌈entry_count / 8⌉ |
| 24 | block_index_offset (u32) = 72 (канонично) |
| 28 | blocks_offset (u32) = 72 + 4·block_count (канонично) |
| 32 | blocks_size (u32) |
| 36 | file_size (u32) = blocks_offset + blocks_size = len(raw) |

Индекс блоков — `block_count` абсолютных u32-оффсетов (бинарный поиск по первым
словам блоков). Блок (K = 8 записей):

```
u8 first_len, first_word[first_len]          # первое слово целиком
(K-1) × { varint prefix_len,                 # общий БАЙТОВЫЙ префикс с первым словом блока
          u8 suffix_len, suffix }            # суффикс
K × varint frequency                         # u32 varint, lossless (max 9 789 553)
```

Каноничность (проверяют оба валидатора): varint только в минимальной форме,
suffix_len ≥ 1, prefix_len ≤ first_len, слово ≤ 128 байт (u8), слова строго
возрастают лексикографически (тот же NFC-lowercase порядок, что в schema 1 —
критично для идентичности выдачи), блок декодируется ровно до следующего оффсета.
Доступ по индексу (`wordAt`/`frequencyAt`) сохранён: блок = i/8, позиция = i%8 —
нужен биграмм-кросс-референсу SIZE-2.

Общий префикс двух валидных UTF-8 строк всегда кончается на границе кодпоинта,
поэтому байтовый префикс безопасен.

## Выбор K (замер на поставляемых словарях, zlib-9)

| K | tat raw | tat zlib | rus raw | rus zlib |
|--:|---:|---:|---:|---:|
| 4 | 1 228 468 | 513 898 | 1 223 108 | 555 112 |
| **8** | **1 162 870** | **502 092** | **1 151 323** | **540 573** |
| 16 | 1 215 591 | 511 323 | 1 201 485 | 550 061 |
| 32 | 1 311 080 | 524 996 | 1 289 230 | 563 013 |

K = 8 — минимум по сжатому размеру у обоих языков и одновременно минимум работы
декода (≤ 7 слов на доступ) среди победителей; K = 4 проигрывает из-за вдвое
большего индекса блоков.

Бюджеты пересмотрены: сжатый 700 000 → **600 000**, сырой 2 936 012 →
**1 400 000** (запас ~10 %/~20 % к измеренному, как у schema 1).

**Дельта APK** (assembleRelease, подписанный): 2 095 592 Б (1.9.8 в `dist/`) →
**1 945 368 Б**, −150 224 Б (−7,2 %). Распакованная дельта содержимого:
assets −199 385 Б; меньше словарной, потому что APK пережимает ассеты
zip-deflate'ом поверх zlib, а более плотный поток schema 2 хуже дожимается.

## Эквивалентность (доказательство lossless)

1. **Полное тождество разбора**: `repack` валидирует вход schema 1 строго и после
   сериализации v2 сверяет (слова, порядок, частоты) кортежами — падение = отказ
   записи. Плюс `scripts/schema2_equivalence_check.py`: `validate_asset(v1)` и
   `validate_asset(v2)` дают идентичные `(words, frequencies)` на обоих словарях
   (100 000 записей каждый).
2. **Все префиксы**: тот же скрипт прогоняет ВСЕ distinct-префиксы длины 1..5 всех
   слов — 41 520 (tat) + 35 319 (rus) = **76 839 префиксов** — через независимую
   модель читателя (бинпоиск по первым словам блоков + последовательный декод,
   та же форма доступа, что у Kotlin-читателя) и сравнивает top-3 кандидатов
   (слова, порядок, частоты) с `prefix_candidates` по разбору v1: **расхождений 0**.
   Плюс 10 000 точечных сверок `word_at`/`frequency_at` на словарь.
3. **Наборы опечаток**: `tests/typo_pack` пересобирает наборы из поставляемого
   словаря — после перехода на schema 2 выход побайтно совпал с записанным
   (`test_real_build_matches_recorded_set_identity`), т.е. слова и порядок,
   видимые генератору, не изменились.
4. **JVM-золотые тесты**: все ожидания, записанные при schema 1, проходят на
   schema 2 без правок ожиданий — `RealDictionaryPrefixIndexTest` (22 записанных
   префикса против query-audit), весь набор `TdictPrefixIndex*` (fuzzy,
   автозамена, ранжирование классов), `ShippedIndexPrefixCoverageTest` (прогон
   всех префиксов каждого седьмого слова обоих словарей с вооружённой таблицей
   соседей — исполняется и D3-проход автозамены).

## Latency (RealDictionaryPrefixIndexTest, одна машина, один прогон методики)

| Метрика | schema 1 | schema 2 |
|---|---:|---:|
| compute median | 0,001 мс | 0,004 мс |
| compute p95 (22 префикса) | 0,007 мс | 0,014 мс |
| худший случай: fanout однобуквенного «к» | 0,057 мс | 0,101 мс |
| request→handoff p95 | 0,013 мс | 0,042 мс |

Худший случай уложен в 2× к schema 1 (и ниже зафиксированного в 1.8.4 worst
0,141 мс). Цена достигнута двумя приёмами в `TdictPrefixIndex`: кэш декодированного
блока (бинарный поиск, `decodeWord`, `frequencyAt`, автозамена) и потоковый обход
диапазона `scanBlockRange` без материализации слов (точный и fuzzy-проходы) —
ноль аллокаций в hot path сохранён, порядок вставок в ранжирование неизменен.

## Миграция на устройстве

`finalFileName` несёт schema-id и raw SHA-256 — оба изменились, значит новое имя
файла: при обновлении словарь один раз переинфлируется рядом со старым, старый
снимается обычной ретенцией хранилища. Кода миграции нет.

## Воспроизведение

```
python3 scripts/dictionary_pack.py repack --asset <v1.zlib> \
    --raw-output out.tdict --asset-output out.tdict.zlib --language tat|rus
python3 scripts/schema2_equivalence_check.py --v1 <v1.zlib> --v2 <v2.zlib> --language tat|rus
python3 scripts/rebuild_assets.py --check --allow-known-drift
```

`dict_accept.py pack` и `dictionary_pack.py build` пишут schema 2 по умолчанию
(`--schema 1` оставлен для справки и golden-тестов v1).
