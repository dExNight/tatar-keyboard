# План: аудит, реструктуризация, очистка и оптимизация tatar-keyboard

**Дата составления:** 2026-08-30. **База:** ветка `codex/version-1.6.0`, HEAD `30387472`, версия 1.9.4 (versionCode 20), дерево чистое.

Решения оператора (приняты при составлении плана):

- локали срезаются до `tt`/`ru`/`en` (включая список ~70 доп. раскладок);
- `docs/` реструктурируется: архив миссий + индекс, через `git mv` (история сохраняется);
- Baseline Profile включается в оптимизацию (без runtime-зависимостей);
- `codex/version-1.6.0` сливается в `main` локально (`merge --no-ff`), push/теги наружу — только руками оператора.

## Зафиксированные ограничения (из BRIEF.md, не нарушать)

- Ноль сторонних **runtime**-зависимостей (dev/build-time инструменты — lint, detekt, Macrobenchmark — допустимы, в APK не попадают).
- Без `INTERNET`, без NDK, без Compose в IME-процессе.
- APK ≤ 3 145 728 Б; холодный старт < 400 мс; ноль аллокаций в цикле отрисовки.
- **Никаких потерь качества/функциональности**: каждая правка, трогающая поведение, закрывается тестом и регрессионным прогоном.
- История git не переписывается; история документов не переписывается (только датированные сноски); ассеты-пины (SHA-256 словарей/биграмм) не меняются без пересборки по конвейеру.
- Наружу (push, тег на origin, релиз в стор) — только оператор.

## Общие правила всех фаз

1. **Каждая фаза = миссия в стиле проекта**: перед стартом — ресерч (интернет + код), отчёт `docs/<ФАЗА>.md` с измеренными числами, APK-аудит при смене артефакта, критерий «ГОТОВО КОГДА» в начале работы.
2. Гейты после каждой фазы: `./gradlew test` (974 JVM-теста), `pytest tests/` (181 тест), `lintVitalRelease`, `scripts/check-no-internet.sh` (исходник + debug + release APK), побайтовый размер release APK.
3. Сборка release подписывается тем же ключом (`98ca6feb…42ad`), keystore не пересоздаётся.
4. Одна фаза = отдельный набор коммитов; содержательные коммиты отделены от «маркерных».

## Риски и открытые вопросы

- **Срез локалей** — самая рискованная правка: `getIdentifier`-резолвы раскладок могут прятать ссылки; mitigations — grep-протокол, эмуляторный прогон всех трёх раскладок, `res/raw/keep.xml` не трогать.
- **Baseline Profile на эмуляторе** может не показать реального эффекта (эмулятор ≠ железо; PSS/живое устройство исторически не меряны) — тогда честно фиксируем «эффект не измерим на эмуляторе», профиль оставляем (вреда нет).
- **Русская таблица биграмм (4 195 разошедшихся голов)** и прочие открытые долги из HANDOFF — **вне scope** этой кампании; отдельные миссии.
- Ожидаемый итог по размеру: ориентировочно −150…−400 КБ (локали, LXX-стабы, arsc); точные числа — после фаз 3–4.
