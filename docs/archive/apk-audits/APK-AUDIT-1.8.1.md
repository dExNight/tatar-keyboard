## Что вошло в 1.8.1 поверх 1.8.0

Ровно одно изменение рабочего кода:
`RichInputConnection.deleteTextBeforeCursor` теперь схлопывает пару границ выделения под
`hasCursorPosition()`, как это делает `commitText` и все остальные мутаторы класса
(`app/src/main/java/rkr/simplekeyboard/inputmethod/latin/RichInputConnection.java:374-393`,
коммит `d725c1e`).

Причина, доказательство и разбор — `docs/TAP-REPRO.md`. Коротко: обычный backspace двигал
`mExpectedSelStart` и не трогал `mExpectedSelEnd`, поэтому после каждого стирания
клавиатура считала, что в поле выделен символ, хотя курсор схлопнут. Из этого следовали
оба симптома:

| Симптом | Механизм |
|---|---|
| тап по подсказке не вставляет слово | `InputLogic.replaceTrailingWord` отказывает на гейте `mConnection.hasSelection()` (`InputLogic.java:557`) раньше, чем посмотрит на слово |
| подсказки не возвращаются после стирания | `LatinIME.onUpdateSelection` принимает собственный backspace клавиатуры за внешний уход курсора (`LatinIME.java:1300-1302`), гасит полосу и не переспрашивает движок |

Вместе с правкой в дерево пришли шесть тестов миссии `tt-tap-repro` и два её отчёта
(`docs/TAP-REPRO.md`, `docs/SILENT-AUDIT.md`) — до этого они лежали незакоммиченными.

Дифф `812e4bf..46f3b3a` по `app/`: четыре файла, +436/−4, из них рабочего кода — девять
добавленных и две удалённые строки. Ресурсы, строки интерфейса и ассеты не тронуты вообще.

## Второй дефект: нужен твой выбор, вопрос отправлен

Миссия `tt-tap-repro` нашла второй дефект полосы подсказок, **не связанный** с симптомами,
которые ты видел. `SuggestionsController.kt:1186-1188`:

```kotlin
if (word != displayedPrefix) {
    displayedPrefix = null
}
```

Кандидаты отвязываются от текущего состояния (это правильная защита от вставки устаревшего
слова), но полоса при этом **не перерисовывается**. Пока не придёт следующий ответ
движка, ты видишь живые кнопки, тап по которым гарантированно ничего не сделает. Обычно
окно длиной в один ответ движка; если ответ будет отброшен любым из гейтов `applyResult`,
окно не закроется вообще.

Это тот самый тест, который стоит `@Ignore`.

Закрывать его — выбор, а не очевидность:

* **A** — гасить полосу вместе с отвязкой (`strip.reserve()` рядом с `displayedPrefix =
  null`). Мёртвых кнопок не будет никогда, но полоса начнёт пустеть на каждой набранной
  букве и заполняться обратно. На бюджетном телефоне это заметное мигание.
* **B** — оставить как есть, признать окно допустимым. Ноль риска и ноль правок.
* **C** — узкая правка: гасить полосу только там, где ответ заведомо не придёт. Убирает
  бесконечное окно, не вызывая мигания, но это проектирование, а не правка на строку.

Вопрос отправлен тебе через `.smgr/tt-version-1.8.1/ask.json` с рекомендацией **B на
1.8.1** и решением между A и C после того, как ты пощупаешь 1.8.1 на телефоне. Ответ ни в
чём не отменяет эту сборку: A и C — отдельная правка поверх.

Важно понимать, что этот дефект **не был причиной** того, что ты видел: доказательство по
твоему скриншоту разобрано в `docs/TAP-REPRO.md`, раздел «Главная версия досье: что с ней
стало».

## Третье следствие: воспроизвести не удалось, из changelog убрано

`docs/TAP-REPRO.md` вывел из чтения кода третье следствие той же причины: пока пара
рассинхронизирована, второй backspace, пришедший раньше системного `onUpdateSelection`,
уходит в `deleteSelectedText()` и удаляет символ **после** курсора. Это была бы порча
текста.

**Проверено на эмуляторе на 1.8.0 — не воспроизвелось ни разу.** Проверялось двумя
способами, оба с курсором в середине строки `Йцукен` (позиция 3):

* удержание backspace 1,2 с (автоповтор) — результат `кен`, то есть удалены ровно три
  символа слева, справа не тронуто;
* два быстрых нажатия одной командой, три повтора — результат `Йкен` каждый раз, то есть
  чисто.

На 1.8.1 те же два способа дают тот же правильный результат. Механизм из кода никуда не
делся, но окно, в котором он срабатывает, короче того, во что попадает `adb input`.

**Что с этим сделано:** первая редакция раздела `[1.8.1]` в `CHANGELOG.md` утверждала, что
1.8.1 чинит пропажу текста справа от курсора при зажатом backspace. Утверждение убрано —
дефекта никто не наблюдал, и обещать его починку пользователю нельзя. `changelogs/12.txt`
поправлен так же. Правка кода при этом путь всё равно закрывает: после схлопывания пары
`hasSelection()` после обычного backspace ложным больше не бывает.

Если ты когда-нибудь заметишь на телефоне, что при зажатом backspace в середине строки
пропадают символы **справа** от курсора, — это оно, и на 1.8.1 его быть не должно.

нет. После первой публикации его потеря означает, что обновить приложение нельзя уже
никогда: сертификат `98ca6feb…` не восстанавливается.

Стоит невыполненным девятый релизный прогон подряд. Это пять минут работы.

### 1. Проверить 1.8.1 на своём телефоне

Установить `dist/tatar-keyboard-1.8.1.apk` поверх 1.8.0 и проверить ровно то, что ты
описывал:

* набрать слово, дописать лишнюю букву, стереть её — **подсказки должны вернуться**;
* сразу после backspace ткнуть в подсказку — **слово должно вставиться**;
* то же самое на русской раскладке (симптом 2 ты видел на обеих);
* заодно: при зажатом backspace в середине строки символы справа от курсора не должны
  пропадать.

Если что-то из этого всё ещё не работает **и без предшествующего backspace** — значит
живёт что-то ещё, и искать надо там, куда указывало твоё уточнение «тап не работал везде»:
в состоянии, переживающем редакторскую сессию. Разбор двух прочтений этого уточнения — в
`docs/TAP-REPRO.md`, раздел «Об уточнении».

### 4. Просмотреть полный diff и сделать release commit

На этой версии diff короткий как никогда: девять добавленных и две удалённые строки в
одном файле плюс тесты.

```sh
git diff 812e4bf..46f3b3a -- app/src/main
git log --oneline 812e4bf..46f3b3a
```

### 5. Публикация

Ничего из этого миссия не делала и делать не имела права:

* `git push` ветки, зелёный CI;
* merge в `main`;
* `git tag -a v1.8.1 -m "Tatar Keyboard 1.8.1"`, push тега;
* GitHub Release с title `Tatar Keyboard 1.8.1`, notes по разделу `[1.8.1]`, вложением
  **именно** `dist/tatar-keyboard-1.8.1.apk` и его SHA-256
  `93ca78547fddd5a803199f8320610b2e3516dc6400eec6a3e11cdc59f0a3b156` в тексте Release;
* заявка в IzzyOnDroid, если публикуешь туда.

Шаги расписаны в `docs/PUBLISH-CHECKLIST.md`, разделы 5–7.

### 6. Решить судьбу 1.5.0 … 1.8.0

Наружу не выходила ни одна из них; на remote только теги `v1.0.1` и `v1.1.0`. Если

вместе, и они написаны так, чтобы читаться подряд. Проверяется
`git ls-remote --tags origin`.
