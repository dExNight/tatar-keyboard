Прогон шагов 1 (частично), 2 («Автоматические локальные gates») и 4 («Финальный
distributable») `docs/PUBLISH-CHECKLIST.md` на кандидате **v1.5.0 / versionCode 7**.

Причина отдельного прогона: после аудита v1.4.0 (`docs/APK-AUDIT-1.4.0.md`) в дерево легла

Проаудированный артефакт v1.4.0 перестал соответствовать дереву, поэтому решением оператора
от 2026-08-20 работа выходит отдельной версией **1.5.0 / versionCode 7**.

**Итог: артефакт собран, подписан и проаудирован полностью, шаги 2 и 4 пройдены на
v1.5.0/versionCode 7.** Все числа получены сегодня на свежей сборке из замороженного
коммита; ни одно не перенесено из прошлых прогонов — включая те, что совпали
(сертификат, permission dump, число actionable tasks).

**Оговорка, унаследованная целиком и без изменений:** подписано релизным ключом от
2026-08-18, а не историческим. Keystore не пересоздавался — тот же файл, тот же сертификат
`98ca6feb…`. Upgrade path с v1.1.0 по-прежнему порван; см. «Подписная идентичность» ниже.

**Одно новое отклонение против v1.4.0**, разобранное в разделе «Размер»: артефакт перестал

## Что осталось сделать оператору

Порядок именно такой; каждый пункт требует его рук.

### 0. До всего остального: бэкап keystore

```sh
cp tatar-keyboard-release.jks keystore.properties <куда-то вне этой машины>
```

Ключ существует в одном экземпляре, вне git, и невосстановим. После первой публикации
потеря ключа означает, что обновить приложение уже нельзя никогда — только новый
`applicationId`. Это единственный пункт, который нельзя отложить «на потом».

### 1. Проверить сборку пальцами на телефоне

Артефакт: `dist/tatar-keyboard-1.5.0.apk` (1 798 198 Б, SHA-256 `29902121…`).

```sh
adb install -r dist/tatar-keyboard-1.5.0.apk
```

Установка поверх сборки, подписанной **историческим** ключом (v1.1.0), не пройдёт —
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`; поверх 1.4.0 с телефона встанет нормально, ключ тот
же. Что стоит проверить именно в этой версии:

- панель открывается долгим нажатием запятой; прокрутка идёт непрерывно через разделы,
  заголовки видны на границах, тап по вкладке скроллит к её разделу;
- «АБВ» и `⌫` в нижних углах не мешают попадать по нижнему ряду эмодзи;
- поиск: тап по пилюле, набор `кот` и `cat`, выбор результата; **в поле ввода должно
  попасть только эмодзи и никогда — буквы запроса**;
- выход из поиска крестиком и backspace на пустом запросе;
- **TalkBack** — единственная непроверяемая здесь вещь и главный риск: включить и пройти
  панель и поиск свайпами. Если он молчит или называет ячейки неправильно, это дефект,
  который надо чинить до публикации, а не после.

Найдётся дефект — правка обнуляет evidence этого отчёта: понадобится новый коммит, новая
сборка и новый аудит с нуля. Это не формальность: SHA-256 и размер в Release должны
описывать тот файл, который люди скачают.

### 2. Решить про целевой бюджет D1

1,7147 MiB против цели 1,7 MiB. Обязательный потолок 3 МБ соблюдён с запасом 43 %, так что
релизу это не мешает. Варианта два: принять новый факт (поиск стоит 55 КБ) и поднять
целевую планку в `BRIEF.md`, либо заказать отдельной миссией сжатие индекса. Второе — после
релиза: сейчас любая правка данных требует пересборки и переаудита.

### 3. Просмотреть полный diff и сделать release commit

```sh
git diff --check
git log --oneline version-1.4.0..version-1.5.0
git diff version-1.4.0..version-1.5.0
```

Кандидат — HEAD ветки `version-1.5.0`, коммит `4283944`. Release commit не создан
намеренно: его содержимое зависит от того, что оператор решит по пунктам 1 и 2.

### 4. Push, merge, CI

```sh
git push origin version-1.5.0
```

Дальше — merge в `main` по своему обычаю и зелёный GitHub Actions **на том самом коммите**,
который пойдёт в тег. Локальный `BUILD SUCCESSFUL` из этого отчёта Actions не заменяет:
раздел 5 чеклиста требует, чтобы CI явно содержал unit tests, `lintVitalRelease`, build,
APK-size и no-INTERNET gates. Отдельным пунктом там же — негативная no-INTERNET ветка,
которая должна давать красный CI именно на permission gate.

### 5. Tag и GitHub Release

```sh
git tag -a v1.5.0 -m "Tatar Keyboard 1.5.0"
git push origin v1.5.0
```

Release: title `Tatar Keyboard 1.5.0`, notes — раздел `[1.5.0]` из `CHANGELOG.md`,
единственный вложенный файл — `tatar-keyboard-1.5.0.apk` из `dist/`. В теле Release стоит
указать SHA-256 `29902121835feb0a3bfa659f22557db8107732422d8e37766dfbd5ea56d1cb83`, чтобы
скачавший мог сверить.
