# SIZE-SCHEMA3 — таблицы биграмм TATBIGR schema 3 (кросс-референс в словарь + varint)

2026-09-01, миссия SIZE-2 кампании ужатия APK (ресерч: `SIZE-OPTIMIZATION-RESEARCH.md`,
пункт 2: 100 % голов и преемников уже есть в основном словаре). Lossless: наборы голов,
списки преемников и их порядок побайтно те же, что у schema 2; поменялась только упаковка.
Читатель schema 2 удалён — весь код работает на schema 3; python-упаковщик schema 2
оставлен для golden/истории (`bigram_asset_pack.py pack --schema 2`), как в SIZE-1.

## Формат (schema_id = 3, format_version = 1)

Заголовок — 128 байт (у schema 2 было 96): те же magic `TATBIGR\0` и 4×u16 меты, затем
10×u32, SHA-256 словаря и контрольная сумма с занулённым полем (трюк тот же, смещение 96):

| Смещение | Поле |
|---|---|
| 16 | head_count (u32) |
| 20 | pair_count (u32) |
| 24 | head_block_count (u32) = ⌈head_count / 64⌉ |
| 28 | block_index_offset (u32) = 128 (канонично) |
| 32 | head_deltas_offset (u32) = 128 + 12·head_block_count (канонично) |
| 36 | head_deltas_size (u32) |
| 40 | counts_offset (u32) = head_deltas_offset + head_deltas_size |
| 44 | success_ids_offset (u32) = counts_offset + head_count |
| 48 | success_ids_size (u32) |
| 52 | file_size (u32) = len(raw) |
| 56 | **raw SHA-256 связанного словаря** (32 Б) |
| 88 | reserved (8 Б, нули) |
| 96 | checksum (32 Б, SHA-256 по файлу с занулённым полем) |

Четыре секции, без паддинга и разделителей:

1. **Блочный индекс голов**: head_block_count записей по 12 Б `{u32 firstDictIndex,
   u32 headDeltaOffset (отн. секции 2), u32 successOffset (отн. секции 4)}` — блок =
   64 головы, бинарный поиск по словарному индексу.
2. **Дельта-поток голов**: внутри блока — (n−1) varint-дельт, каждая ≥ 1. Головы
   отсортированы кодпоинтно, словарь — тоже, поэтому словарные индексы голов строго
   возрастают и дельта-кодирование lossless.
3. **Счётчики преемников**: head_count × u8 (у поставляемых таблиц все = 1..4).
4. **Преемники**: pair_count varint-индексов прямо в словарь, в порядке упаковки
   (count desc, tie code-point asc). Дедуп-блоб преемников и оба u32-массива оффсетов
   schema 2 исчезли совсем.

Связка версий: таблица валидна только с конкретным словарём. Заголовок называет его raw
SHA-256; `BigramArtifactSpec.expectedDictionaryRawSha256` пинит его в контракте;
`TatBigrValidator` fail-closed при несовпадении с пином, `TatBigrPrefixIndex.open` — при
несовпадении с фактическим словарём движка (и проверяет ВСЕ индексы < entryCount);
`rebuild_assets.py --check` сверяет пин связки с замеренным SHA словаря. Голова или
преемник вне словаря теперь **невыразимы** — упаковщик падает fail-closed, класс дрейфа
«heads_outside_dictionary» закрыт конструкцией.

## Размеры

| Ассет | schema 2 zlib | schema 3 zlib | Δ | v2 raw | v3 raw |
|---|---:|---:|---:|---:|---:|
| tatar_bigrams | 176 749 | **81 028** | −95 721 (−54 %) | 520 892 | 134 664 |
| russian_bigrams | 149 118 | **63 312** | −85 806 (−58 %) | 465 610 | 131 662 |
| **Σ** | 325 867 | **144 340** | **−181 527** | 986 502 | 266 326 |

Замер лучше ресерч-оценки (~120 КБ), потому что преемники ушли в varint-индексы словаря
целиком, а не в собственный дедуп-блоб. Бюджеты валидатора (сжатый 250 000, сырой
1 048 576) не пересматривались — они стали ещё просторнее.

**Дельта APK** (assembleRelease, подписанный): 1 945 368 Б (дерево SIZE-1) →
**1 794 796 Б**, −154 572 Б (−7,9 %). Против 1.9.8 (2 095 592 Б в `dist/`) две миссии
дают суммарно −300 796 Б (−14,4 %). Как и в SIZE-1, APK-дельта меньше сжатой дельты
ассетов: zip-deflate поверх более плотного потока дожимает хуже.

## Эквивалентность (доказательство lossless)

1. **Репак**: `bigram_asset_pack.py repack` строится из валидированного разбора v2 и после
   сериализации v3 сверяет головы и списки преемников кортежами — расхождение = отказ
   записи. Корпуса не нужны: содержимое переносится побайтно-пословно.
2. **Независимая проверка**: `scripts/schema3_equivalence_check.py` (зеркало
   `schema2_equivalence_check.py`) — полный разбор обоих схем плюс НЕЗАВИСИМАЯ модель
   читателя v3 (бинпоиск блока по словарному индексу, потоковый декод дельт и
   varint-преемников, резолв через плоский список слов словаря). Прогнаны ВСЕ головы обеих
   таблиц: 10 204 tat + 9 998 rus = **20 202 головы, 80 683 пары** — пословно и по порядку
   идентичны; плюс 5 283 + 5 001 слов-не-голов — читатель молчит, как положено.
   Расхождений 0.
3. **JVM-золотые тесты**: наборы TatBigr*/RealBigram*/BigramStore/Suggestions* проходят на
   schema 3; committed-ассеты пинятся числами (10 204/40 734/134 664 и
   9 998/39 949/131 662).

## Latency (RealBigramPrefixIndexTest, та же методика и машина)

| Метрика | schema 3 |
|---|---:|
| compute median | 0,003 мс |
| compute p95 | 0,064 мс |
| request→handoff p95 | 0,011 мс |

Бюджет E5c — compute p95 ≤ 5 мс: запас два порядка. Чтение v3 — один точечный бинпоиск в
словаре (с блочным кэшем), бинпоиск блока голов, ≤ 63 varint-дельт и ≤ 4 varint-преемника —
работа того же порядка, что у schema 2, при нуле аллокаций вне строк результата.

## Эмулятор (tt_suggest_a14, debug APK)

Штатный смоук DEV-3: **18 PASS / 0 FAIL / 1 SKIP** (en — by design), включая оживление
полосы подсказок на обеих словарных раскладках (`build/emulator-smoke-schema3/`).
Next-word на живом IME (скриншоты `build/nextword-schema3/`, эфемерно):

- ru «я в » → **этом · том · результате** — точное совпадение с контрактом;
- tt «ул кил » → **дә · әле · һәм** — точное совпадение;
- tt «ул мин » → **дә · аны · бу** — отличается от снимка 1.9.7 (дә·үзем·бу) ровно так же,
  как отличается поставленная schema-2 таблица 1.9.8 (разговорная перепаковка): проверено
  прямым разбором старого ассета — `мин → дә, аны, бу, үзем`. Не расхождение схемы, а
  актуальное содержимое таблицы.

Тонкость сценария: контекст, начинающийся с нулевого символа поля, by design молчит
(`TatarWordUtils.extractNextWordContext` консервативно отсекает слово у края кэша) —
поэтому контроль снимался с ведущим словом («ул кил », а не «кил »).

## Миграция на устройстве

`finalFileName` несёт schema-id (`s3`) и новый raw SHA-256 — новое имя файла: при обновлении
таблица один раз переинфлируется рядом со старой, старая снимается ретенцией хранилища.
Кода миграции нет. Таблица, оказавшаяся рядом с чужим словарём, не открывается (связка по
SHA-256) — предсказания молчат, ввод не затрагивается.

## Воспроизведение

```
python3 scripts/bigram_asset_pack.py repack \
    --v2 <schema2.tatbigr.zlib> --dictionary <dict.tdict.zlib> \
    --out-raw out.tatbigr --out-compressed out.tatbigr.zlib --language tat|rus
python3 scripts/schema3_equivalence_check.py --v2 <schema2.zlib> --v3 out.tatbigr.zlib \
    --dictionary <dict.tdict.zlib> --language tat|rus
python3 scripts/rebuild_assets.py --check --allow-known-drift
```

`bigram_asset_pack.py pack` пишет schema 3 по умолчанию (`--schema 2` оставлен для
golden-тестов и истории, как `--schema 1` у словарей в SIZE-1). Полная пересборка
`rebuild_assets.py` (с корпусами) пакует таблицы сразу в schema 3 от свежих словарей.
