# Майлстоун v1.1 — «Татарский первым классом»

Старт: 2026-07-20, после завершения iOS-редизайна. Ведение — docs/ (GSD обойдён по решению
пользователя). Конвейер каждой фазы: implement → build+gates → adversarial review
(fail-closed гейт) → commit → push.

Рамки: ноль новых зависимостей, без INTERNET, APK ≤ 3 МБ (финальный APK v1.1.0 —
832 442 байта, около 813 КиБ), ноль аллокаций
в draw-цикле, юр-рамки iOS-стиля. Новые строки — en base + ru + tt.

## Фаза T — татарская локализация интерфейса (values-tt)

Главный гэп против core value (вскрыт ревью v1.0): системная локаль tt даёт английский UI,
TalkBack по-татарски невозможен. Терминология — по глоссарию tt.wikipedia и локализации
Тиз.Яз: төймәсар (клавиатура), төймә (клавиша), көйләүләр (настройки), тел (язык),
хәреф (буква). Перевод вычитывает пользователь (носитель).

## Фаза R — ресерч словаря/автокоррекции (ЗАВЕРШЕНА 2026-07-20, три отчёта)

- [x] R1. Формат: кириллические/тюркские словари AOSP-формата ~6–10 байт/словоформа
  (main_ru 220k = 2,14 МБ; казахский прецедент есть, татарского словаря нет ни у кого).
  НО: нативного движка в нашем форке нет (JNI вырезан, констрейнт «без NDK») → для D1
  свой ПРОСТОЙ формат: сортированный массив словоформ+частот, mmap несжатым из APK
  (noCompress), бинарный поиск по префиксному диапазону, top-3 по частоте. Trie/DAWG —
  оптимизация позже. mmap почти не ест PSS (clean file-backed pages).
- [x] R2. Источники/лицензии: БАЗА — Leipzig Corpora tat_* (готовые words.txt
  словоформа+частота, CC BY — совместимо с Apache-2.0 через NOTICE; tat_mixed_2015 +
  tat_web_2018 + tat_news ≈ 50 млн токенов). Добор/чистка — HPLT tat_Cyrl (CC0) и
  MADLAD-400 (CC-BY); валидация — Common Voice tt (CC0). corpus.tatar — «только
  наука/учёба», БЕЗ письма-разрешения не использовать (написать tatcorpus@gmail.com —
  их данные лучшие). apertium-tat (GPL) — НЕ использовать для словника без разрешения.
  ru — тот же конвейер из Leipzig ru_* (или HeliBoard experimental main_ru, он из
  Leipzig). Оформление — модель wordfreq: код Apache-2.0, словарь-файл CC BY + NOTICE.
- [x] R3. Composing НЕ включать: подсказки и даже автозамена делаются паттерном
  delete+commit (как рабочий double-space); включение composing в 2–3 раза дороже и
  ревизует RichInputConnection (главный протестированный актив) + возвращает WebView-
  проблемы. Suggestion-движок upstream вырезан в 2017 — писать с нуля, но живые хуки
  есть: mShouldShowSuggestions (готовый password-гейт), кэш текста у курсора
  (синхронный на UI-потоке), single-thread executor, паттерн delete+commit+revert.
- [x] R4. UI: полоса 40dp / 3 ячейки СТЕКОМ над пятым рядом (решение research/07),
  ViewStub в input_view.xml — ленивый инфлейт, ноль влияния при выключенной опции;
  Canvas-отрисовка без аллокаций. ГЛАВНЫЙ РИСК: onComputeInsets/touchable region
  (LatinIME.java:535, getVisibleKeyboardView) — без правки тапы по полосе не дойдут;
  тестировать первым делом на устройстве.
- [x] R5. ВЕРДИКТ — план словарных фаз (следующий майлстоун v2):
  - D0 (полдня, скрипт): скачать Leipzig tat_*, посчитать кумулятивное покрытие
    топ-100k/150k/250k — снять последний риск данных ДО кода; письмо в corpus.tatar
  - D1: полоса с 3 подсказками по префиксу, tt-словарь ~150k форм (~1,2–1,5 МБ mmap),
    без автозамены, opt-in (дефолт выкл), без composing. 4 подфазы: формат+пайплайн
    словаря; движок+threading (generation-счётчик, guard рассинхрона кэша);
    UI-полоса+insets; настройка+гейты (password уже готов)
  - D2: ru-словарь (~60–100k форм, тот же конвейер), переключение словаря по subtype
  - D3: автозамена на пробеле с revert по backspace (паттерн mJustDoubleSpaced),
    отдельный тумблер, только после обкатки качества словаря
  - Бюджет: APK после D1+D2 ≈ 2,6–2,9 МБ — впритык; запасной ход — deflate-хранение
    с распаковкой в filesDir (−30–40% в APK)
