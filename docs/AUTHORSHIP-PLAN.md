# AUTHORSHIP-PLAN — как убрать Claude из авторства коммитов (2026-09-02)

Запрос оператора: автором коммитов должен быть только оператор. План работ.

## Фактическое состояние (замерено)

- Поле **автора** коммитов чистое: 516 коммитов — `dExNight <am.gubaidullin@…>`,
  остальные — авторы апстрим-форка (rkkr и др., трогать нельзя и не нужно).
- Claude присутствует только как **трейлер `Co-Authored-By: Claude …`** в теле
  сообщения: **226 коммитов**, все в диапазоне `6c1ddd7a`…`30387472`
  (эпоха codex-веток; кампании на main после 2026-08-30 трейлеров не содержат).
- GitHub показывает таких соавторов в UI и в списке Contributors — именно это,
  судя по всему, и беспокоит.

## Вариант A (рекомендуется): закрыть будущее, историю не трогать

1. **Запретить трейлеры на уровне машины**: `git config commit.template` или
   hook `.githooks/commit-msg`, который fail-closed отклоняет сообщение с
   `Co-Authored-By: Claude` (и любым `Co-[Aa]uthored-[Bb]y` от инструментов);
   подключить через `git config core.hooksPath .githooks` (коммитится в репо —
   сработает у любого агента/инструмента, работающего с этим деревом).
2. **Убрать источник**: в настройках инструментов, добавляющих трейлер
   (`.claude/settings.json` — `includeCoAuthoredBy: false` или аналогичный
   параметр; для kimi-code проверить конфиг), чтобы новые сессии не добавляли.
3. **Зафиксировать правило** в `AGENTS.md`: «в коммитах нет Co-Authored-By».
4. Проверка: `git log --grep='Co-Authored-By'` на новых коммитах пуст; hook
   ловит тестовый коммит с трейлером (доказательство в отчёт).

Цена: ~1 час. Риск: ноль. История остаётся как есть — 226 старых коммитов
сохранят трейлеры, но новых не появится никогда.

## Вариант B: переписать историю (убрать трейлеры из всех 226 коммитов)

Механика: `git filter-repo --message-callback` с regex-вырезанием трейлеров.

**Цена и последствия (все неотвратимы):**
- Меняется SHA-256 **каждого** коммита после первого тронутого — то есть почти
  всей истории проекта. Это прямо нарушает зафиксированную дисциплину
  «историю не переписываем» (AGENTS.md, миссионный воркфлоу).
- **Дохнут все ссылки на хэши в документации**: docs/ и HANDOFF.md содержат
  сотни ссылок вида `30387472` (аудиты, отчёты миссий, пометки «закрыто в
  коммите X»). Нужна мапа старый→новый и массовая правка документов — что само
  по себе нарушает второе правило «содержимое отчётов не переписываем».
- Теги (v1.0.1, v1.1.0, v1.9.4) пересоздаются; старые подписи коммитов/тегов
  (если были) инвалидируются.
- Требуется **force-push** с перезаписью опубликованной истории на GitHub;
  все существующие клоны ломаются.
- GitHub закэшировал старые коммиты: они останутся доступны по старым SHA
  (commit-gc не мгновенный) — полного «исчезновения» трейлеров всё равно нет.
- Публикационный аспект: для IzzyOnDroid заявлено AI-раскрытие (чек-лист);
  история без трейлеров при заявленном раскрытии — не противоречие, но
  расхождение «в истории чисто, в заявке честно» стоит осознать.

**Если оператор всё же выбирает B — протокол:**
1. Полный бэкап: `git clone --mirror` в отдельный каталог + `backup/*` ветки.
2. `git filter-repo --message-callback 're.sub(r"\n*Co-Authored-By: Claude[^\n]*", "", m)'`
   на main; мапа хэшей `old→new` сохраняется в `docs/authorship-remap.tsv`.
3. Скриптом обновить все ссылки на хэши в живых документах (архивные отчёты —
   решить отдельно: либо мапа-справочник без правок, либо правки с датированной
   пометкой).
4. Пересоздать теги на новых хэшах; проверить сборку из переписанного HEAD
   (гейты + воспроизводимость).
5. Force-push (только по явной команде оператора), удаление старых refs,
   GitHub: проверить, что PR/issues ссылки не сломались.
6. Гейты: JVM/python/lint/no-internet на переписанном дереве; smoke.

Цена: день работы + необратимый риск. Выигрыш: косметический (трейлеры уходят
из прошлого, которое уже никто не читает).
