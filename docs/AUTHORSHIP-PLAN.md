# AUTHORSHIP-PLAN — вариант B: переписывание истории (убрать Co-Authored-By: Claude)

Дата: 2026-09-02. Решение оператора: вариант B, несоответствие хэшей коммитов
в документах — принято («пофиг»), ссылки в docs/HANDOFF НЕ обновляем.
Цель: в истории не остаётся ни одного трейлера `Co-Authored-By: Claude …`
(226 коммитов, диапазон `6c1ddd7a`…`30387472`), авторы не меняются
(dExNight и авторы апстрима остаются как есть — меняются только тела сообщений).

## Неотвратимые последствия (приняты оператором)

- SHA-256 меняется у каждого коммита после `6c1ddd7a` (почти вся история).
- Теги v1.0.1, v1.1.0, v1.9.4 будут пересозданы на новых хэшах.
- Хэши в docs/ и HANDOFF.md станут неразрешимыми — осознанно оставляем.
- Опубликованная история на GitHub перезаписывается force-push; старые
  коммиты остаются в кэше GitHub некоторое время (полного исчезновения нет).
- Текущий `dist/tatar-keyboard-1.9.12.apk` остаётся валидным артефактом:
  он собран из дерева, содержимое дерева переписывание не меняет
  (меняются только сообщения коммитов).

## Протокол

### Шаг 0. Страховка

1. `git clone --mirror . /tmp/tatar-keyboard-mirror-backup` — полная копия
   со всеми refs (ветки, теги).
2. Локальная ветка-указатель: `git branch backup/pre-filter-repo` на HEAD.
3. Проверка: `git -C /tmp/tatar-keyboard-mirror-backup log --oneline -1` и
   список тегов совпадают с оригиналом.

### Шаг 1. Инструмент

- `git filter-repo` — единственный поддерживаемый путь (filter-branch
  deprecated). Проверить наличие: `git filter-repo --version`. Если нет —
  один файл `git-filter-repo` (python) в /tmp, без системной установки;
  пин по SHA-256 с релиза upstream.
- Тестовый прогон на копии: `cp -r` репозитория в /tmp, прогон там,
  сверка дерева.

### Шаг 2. Переписывание

```
git filter-repo --force --message-callback '
import re
return re.sub(rb"\n*Co-Authored-By: Claude[^\n]*\n?", b"\n", message)'
```

- Проверка результата: `git log --format='%B' | grep -ci 'claude'` → 0
  (единственное легитимное «claude» — путь `.claude/CLAUDE.md` в телах;
  regex его не трогает: он не в трейлере; проверить, что остаточные
  вхождения — только пути/контент, не Co-Authored-By).
- Проверка: `git log --format='%an <%ae>' | sort | uniq -c` — состав авторов
  идентичен исходному (516 dExNight + апстрим).
- Проверка деревьев: `git diff backup/pre-filter-repo HEAD` — пусто
  (деревья идентичны, менялись только сообщения).

### Шаг 3. Теги и ветки

- Теги пересоздаются автоматически filter-repo (аннотированные — с новыми
  хэшами). Проверить: `git tag -l` и `git show v1.9.4` указывают на новый
  хэш финала 1.9.4.
- Ветка `backup/pre-restructure` — удалить или переписать вместе (она внутри
  истории); `backup/pre-filter-repo` оставить до конца.

### Шаг 4. Валидация переписанного дерева

- Гейты на новом HEAD: JVM 1085, python 348, lintRelease, check-no-internet,
  assembleRelease — всё зелёное (дерево не менялось, ожидаемо, но прогнать).
- Воспроизводимость: два прогона release_pack.sh → один SHA-256.
- `git fsck` чистый.

### Шаг 5. Публикация (только по явной команде оператора)

1. `git push --force origin main` (+ `--force` для тегов:
   `git push --force origin --tags`).
2. Проверить на GitHub: main зелёный, теги на месте, Releases (если будут)
   привязаны к новым тегам.
3. CI на новом HEAD — зелёный.

### Шаг 6. Финал

- `backup/pre-filter-repo` удалить после подтверждения оператора;
  mirror-бэкап в /tmp удалить после публикации.
- Датированная пометка в HANDOFF.md: история переписана 2026-09-02,
  хэши до `6c1ddd7a` неизменны, всё после — новые хэши; ссылки на хэши
  в архивных документах ведут на старую историю (не разрешаются) — принято.
- AGENTS.md: правило «историю не переписываем» дополнить датированной
  сноской о единичном исключении 2026-09-02.

### Шаг 7. Будущее (из варианта A — в любом случае)

- Hook `.githooks/commit-msg` (fail-closed против `Co-Authored-By`) +
  `core.hooksPath`; выключить добавление трейлера в конфигах инструментов;
  правило в AGENTS.md.

## Откат

До шага 5 — тривиальный: `git reset --hard backup/pre-filter-repo`,
вернуть refs из mirror. После force-push — восстановление через mirror-бэкап
+ второй force-push (GitHub помнит старые SHA, reflog на сервере недоступен).

## ГОТОВО КОГДА

`git log --format='%B'` не содержит `Co-Authored-By` ни в одном коммите,
авторы не изменены, деревья идентичны старой истории, теги пересозданы,
гейты зелёные на новом HEAD, пометки в HANDOFF/AGENTS на месте. Шаг 5 —
по отдельной команде оператора.
