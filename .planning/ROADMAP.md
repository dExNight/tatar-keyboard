# Roadmap: Tatar Keyboard

**Created:** 2026-07-18
**Milestone:** v1.0 — MVP + релиз (release-ready APK ≤ 3 МБ, privacy policy, GitHub Releases + заявка IzzyOnDroid)
**Mode:** mvp (Vertical MVP) · **Granularity:** fine

## Overview

11 маленьких вертикальных фаз: от собирающегося форка Simple Keyboard до подписанного релиза. Каждая фаза завершается **собирающимся и устанавливаемым APK** — клавиатурой можно пользоваться после каждой фазы, эргономика пятого ряда проверяется вживую с фазы 2.

Сквозные дисциплины (не отдельные фазы, а правила каждой фазы):

- **Матрица InputConnection** — главный источник багов IME (WebView keyCode 229, password-поля, MIUI). Smoke-тест матрицы входит в критерии каждой фазы ввода/UI, полный проход — фаза 8.
- **Ноль аллокаций в горячем пути** — закладывается при написании кода (Paint/Rect как поля, точечный invalidate), а не после. Финальный замеренный контроль бюджетов (PERF-01..03) — фаза 11.
- **Без INTERNET** — CI-проверка манифеста с фазы 1 на каждом коммите (PERF-04).

## Phases

### Phase 1: Форк и hello-world

**Goal:** Форк Simple Keyboard собирается под уникальным applicationId и печатает из коробки — фундамент, через который читается «учебник по IME».
**Mode:** mvp
**Requirements:** PERF-04
**Depends on:** —
**Progress:** 01-01 ✓ (Task 5 device-verify deferred) · 01-02 ✓ локальная часть (keystore + подписанный assembleRelease + ci.yml; GitHub-репо/push/прогоны CI и device-verify — deferred, см. 01-02-SUMMARY.md)

Форк rkkr/simple-keyboard, новый applicationId (рабочее имя фиксируется здесь), Kotlin подключён через interop, keystore создан (задел под REL-01, финальная верификация — фаза 11), CI-проверка отсутствия разрешения INTERNET.

**Success Criteria:**

1. Debug- и release-APK собираются и устанавливаются на устройство; клавиатура включается в системных настройках и печатает в реальном приложении (сток-раскладки базы).
2. applicationId уникален — приложение ставится рядом с оригинальным Simple Keyboard без конфликта.
3. CI на каждом коммите проверяет манифест и падает, если появляется разрешение INTERNET (PERF-04).
4. Kotlin-код участвует в сборке через interop с Java-базой (тестовый файл собирается и вызывается).
5. Keystore создан, `assembleRelease` даёт подписанный APK.

### Phase 2: Татарская раскладка

**Goal:** Пользователь печатает по-татарски: стандартная ЙЦУКЕН + отдельный видимый пятый ряд `ә ө ү җ ң һ`; раскладки — данные, не код.
**Mode:** mvp
**Requirements:** LAYOUT-01, LAYOUT-04, LAYOUT-05
**Depends on:** Phase 1

Ядро ценности (пятый ряд — дифференциатор, которого нет у Gboard/SwiftKey/Яндекса) до любой косметики. Формат раскладок-как-данных (XML) закладывается сразу и должен допускать латиницу Zamanälif позже без правки движка.

**Success Criteria:**

1. На устройстве печатается татарский текст: все буквы ЙЦУКЕН + все шесть букв пятого ряда вводятся тапом (LAYOUT-01).
2. Слои `?123` и `#+=` открываются и возвращают к буквам (LAYOUT-04).
3. Раскладка описана XML-данными: правка XML меняет раскладку без изменения Java/Kotlin-кода движка (LAYOUT-05).
4. APK собирается и устанавливается; smoke-тест матрицы: татарский ввод работает в Telegram, Chrome/WebView и password-поле.

### Phase 3: Языки и переключение

**Goal:** Три языка как system subtypes (tt_RU / ru / en_US), глобус, long-press дубли татарских букв на обеих кириллических раскладках.
**Mode:** mvp
**Requirements:** LAYOUT-02, LAYOUT-03, SWITCH-01, SWITCH-02
**Depends on:** Phase 2

**Success Criteria:**

1. Пользователь печатает на русской (ЙЦУКЕН) и английской (QWERTY) раскладках (LAYOUT-03).
2. Long-press на а/о/у/ж/н/х/э/г вставляет ә/ө/ү/җ/ң/һ/ә/һ — и на татарской, и на русской раскладке (LAYOUT-02).
3. Система видит три subtype tt_RU/ru/en_US; активная раскладка сохраняется между переключениями приложений (SWITCH-01).
4. Тап по глобусу циклически переключает tt→ru→en; long-press открывает системный пикер IME (SWITCH-02).
5. APK собирается; smoke-тест матрицы: переключение и ввод работают в Telegram, WebView и password-поле (на MIUI — если устройство доступно).

### Phase 4: Механика ввода — регистр и служебные клавиши

**Goal:** Полный цикл ввода символьного уровня: shift/caps-lock, автокапитализация, backspace по кодпоинтам с автоповтором, Enter по imeOptions.
**Mode:** mvp
**Requirements:** INPUT-01, INPUT-02, INPUT-03, INPUT-04
**Depends on:** Phase 3

Механика до скина: скин рисует состояния механики (регистр, подсветка), обратный порядок — двойная работа. Без composing-текста: коммит сразу, удаление `deleteSurroundingTextInCodePoints` (митигация зоопарка InputConnection).

**Success Criteria:**

1. Shift в трёх состояниях: off / один тап (одна заглавная) / двойной тап (caps-lock); регистр букв на клавишах визуально меняется (INPUT-01).
2. Первая буква предложения автоматически заглавная в полях с автокапитализацией; в полях без неё (например, email) — нет (INPUT-02).
3. Backspace удаляет ә/ө/ү и любые не-BMP символы за одно нажатие (по кодпоинтам) и ускоряется при удержании (INPUT-03).
4. Enter показывает и выполняет действие поля: поиск в браузере, «отправить» в мессенджере, перенос строки в заметках (INPUT-04).
5. APK собирается; smoke-тест матрицы: backspace и Enter корректны в WebView (сценарий keyCode 229) и password-полях.

### Phase 5: Механика ввода — жесты и multi-touch

**Goal:** Жестовая механика быстрой печати: двойной пробел — точка, свайп по пробелу — курсор, двупальцевый ввод без потери букв.
**Mode:** mvp
**Requirements:** INPUT-05, INPUT-06, INPUT-07
**Depends on:** Phase 4

**Success Criteria:**

1. Двойной тап по пробелу вставляет точку с пробелом (INPUT-05).
2. Свайп по пробелу перемещает курсор по тексту (INPUT-06).
3. Быстрая печать двумя пальцами не теряет буквы: второе касание коммитит первую клавишу (INPUT-07).
4. APK собирается; smoke-тест матрицы: жесты и multi-touch работают в Telegram и WebView, не срабатывают ложно в password-полях.

### Phase 6: iOS-скин — Canvas-отрисовка и темы

**Goal:** Новый KeyboardView: Canvas-отрисовка по зафиксированной iOS-геометрии и палитре, светлая/тёмная тема — при работающем поверх него всём вводе фаз 2–5.
**Mode:** mvp
**Requirements:** UI-01
**Depends on:** Phase 5

Самая объёмная переписка кода в проекте — потому отдельная фаза и после стабильной механики. Дисциплина PERF-03 пишется в код здесь: все Paint/Rect — поля, точечный invalidate, ноль аллокаций в onDraw (финальный замер — фаза 11). Каркас ExploreByTouchHelper закладывается при первой версии KeyboardView (прикручивать потом — больно); полная верификация TalkBack — фаза 9. Юридические границы: геометрия и палитра — можно; SF Pro, SF Symbols, звуки Apple — запрещены (Roboto, свои VectorDrawable).

**Success Criteria:**

1. Клавиатура отрисована по палитре (светлая #D4D6DD/#FFF/#B3B7C0, тёмная #2C2C2C/#6B6B6B/#474747), радиус ~5dp, 1dp-тень; тема следует системной светлой/тёмной без перезапуска (UI-01).
2. Ни одного ассета Apple: шрифт Roboto, иконки — собственные VectorDrawable.
3. В onDraw/onTouchEvent нет аллокаций по code review и Profiler; во время печати нет GC-событий (дисциплина PERF-03).
4. APK собирается; весь ввод фаз 2–5 (раскладки, слои, shift, жесты) работает поверх нового рендера; smoke-тест матрицы: WebView и password-поле.
5. KeyboardView имеет делегат ExploreByTouchHelper (каркас; озвучка верифицируется в фазе 9).

### Phase 7: iOS-скин — превью, панель, отклик

**Goal:** «Живость» iOS-клавиатуры: мгновенный баллон-превью, long-press панель альтернатив, хаптика и звук на ACTION_DOWN.
**Mode:** mvp
**Requirements:** UI-02, UI-03, UI-04
**Depends on:** Phase 6

Баллон и панель рисуются в слое клавиатуры (не PopupWindow — на MIUI PopupWindow-превью режутся и лагают).

**Success Criteria:**

1. При нажатии буквенной клавиши баллон-превью появляется мгновенно на ACTION_DOWN, отрисован в слое клавиатуры, не PopupWindow (UI-02).
2. Long-press открывает панель альтернатив; выбор — скольжением пальца без отрыва (UI-03).
3. Подсветка клавиши, хаптика KEYBOARD_TAP и системный звук клика срабатывают на ACTION_DOWN; звук и вибрация отключаемы (пока программно; UI-настройки — фаза 10) (UI-04).
4. APK собирается; smoke-тест матрицы: превью и панель не ломают ввод в WebView и password-полях; баллоны не обрезаются краями экрана.

### Phase 8: Совместимость

**Goal:** Клавиатура корректна в проблемных окружениях — полный проход тестовой матрицы InputConnection.
**Mode:** mvp
**Requirements:** COMPAT-01, COMPAT-02, COMPAT-03, COMPAT-04, COMPAT-05
**Depends on:** Phase 7

Smoke-тесты шли в каждой фазе; здесь — систематический полный проход и добивание найденного: password-поля, WebView/keyCode 229, edge-to-edge API 35+ (insets через InputViewContainer), ландшафт, directBootAware, MIUI/HyperOS/One UI.

**Success Criteria:**

1. В password-полях текст вводится корректно, без подсказок и обучения (COMPAT-01).
2. Полный цикл ввода (буквы, backspace, Enter, long-press, жесты) работает в Chrome и WebView — сценарий keyCode 229 (COMPAT-02).
3. На API 35+ клавиатура не перекрыта системными панелями: edge-to-edge и WindowInsets корректны (COMPAT-03).
4. В ландшафтной ориентации клавиатура работает и корректно выглядит (COMPAT-04).
5. APK собирается; клавиатура доступна до первой разблокировки устройства (directBootAware, COMPAT-05); полный проход матрицы (Telegram, Chrome/WebView, пароли, MIUI/One UI, ландшафт) зафиксирован письменно.

### Phase 9: Доступность

**Goal:** TalkBack-пользователь может печатать на татарской клавиатуре.
**Mode:** mvp
**Requirements:** A11Y-01, A11Y-02
**Depends on:** Phase 8

Каркас ExploreByTouchHelper заложен в фазе 6 — здесь полная реализация и верификация с включённым TalkBack.

**Success Criteria:**

1. TalkBack озвучивает каждую клавишу при исследовании касанием; каждая клавиша — виртуальный узел ExploreByTouchHelper (A11Y-01).
2. Татарские буквы имеют понятные контент-описания (например, «татарская э» для ә) и озвучиваются ими (A11Y-02).
3. С включённым TalkBack реально набирается и отправляется слово в мессенджере.
4. APK собирается; обычный (не-TalkBack) ввод не деградировал — smoke-тест матрицы: Telegram и WebView.

### Phase 10: Онбординг и настройки

**Goal:** Новый пользователь доходит от установки до татарского ввода без инструкций; звук и вибрация управляются из настроек.
**Mode:** mvp
**Requirements:** SETUP-01, SETUP-02
**Depends on:** Phase 9

**Success Criteria:**

1. Онбординг-экран ведёт через два шага — «Включить клавиатуру» и «Выбрать клавиатуру» — со статусами выполнения, открывая нужные системные экраны (SETUP-01).
2. В настройках включаются/выключаются звук клика и вибрация — и это реально меняет отклик клавиатуры (SETUP-02).
3. Чистая установка на новом устройстве: пользователь без подсказок доходит от иконки приложения до напечатанного «ә» в мессенджере.
4. APK собирается; smoke-тест матрицы не деградировал.

### Phase 11: Производительность и релиз

**Goal:** Замеренные бюджеты производительности + подписанный релиз + публикация — граница майлстоуна v1.0.
**Mode:** mvp
**Requirements:** PERF-01, PERF-02, PERF-03, REL-01, REL-02, REL-03
**Depends on:** Phase 10

Дисциплина (ноль аллокаций, ленивая инициализация, minify) закладывалась по ходу — здесь финальная измеренная верификация на бюджетном устройстве (Xiaomi/Redmi или Samsung A-серия) и публикация. Перед релизом закрыть открытые вопросы: minSdk 24 vs 26, финальное название/applicationId.

**Success Criteria:**

1. Подписанный release-APK ≤ 3 МБ — замер зафиксирован (PERF-01, REL-01).
2. PSS показанной клавиатуры ≤ 30 МБ (`dumpsys meminfo`) и холодный старт до показа < 400 мс — замеры на бюджетном устройстве зафиксированы (PERF-02).
3. Во время печати: 0 аллокаций в onDraw/onTouchEvent, 0 GC-событий (Profiler), janky-кадры ~0% (`gfxinfo`) (PERF-03).
4. Privacy policy («данные не собираются», без разрешения INTERNET) опубликована и слинкована из README (REL-02).
5. Релиз опубликован на GitHub Releases (APK + changelog) и подана заявка в IzzyOnDroid (REL-03).

## Phase Ordering Rationale

- **Вертикальные слайсы:** после каждой фазы клавиатурой можно пользоваться; эргономика пятого ряда проверяется с фазы 2 (замена пропущенного «этапа 0»).
- **Раскладка до механики, механика до скина:** раскладка в форке — правка данных (быстрый выигрыш ядра ценности); скин рисует состояния механики — обратный порядок дал бы двойную работу.
- **Скин разбит на две фазы** (рендер → интерактив): самая объёмная переписка кода, fine-гранулярность держит каждую фазу собираемой.
- **Совместимость и доступность отдельно, но не «в конце»:** smoke-тесты матрицы InputConnection — в критериях каждой фазы ввода/UI; каркас a11y — при первой версии KeyboardView (фаза 6).
- **Производительность:** дисциплина в каждой фазе, замеренная верификация — фаза 11 (граница майлстоуна).
