# Plan 06-01 — iOS-скин: тема Tatar (id=7), layer-list drawables с 1dp-тенью, иконки, PERF-фиксы, a11y-каркас (wave 1)

**Goal:** Закрыть UI-01 (SC1–SC5) по маршруту (b) из 06-RESEARCH.md §7: iOS-вид достигается **XML-диффом** поверх существующей системы тем форка — новая тема id=7 «Tatar» (styles + light/night цвета + 3 selector→layer-list drawables с ручной 1dp-тенью), перерисовка path'ов иконок shift/shift_locked/globe. Java-дифф хирургический: регистрация темы в KeyboardTheme.java, 3 PERF-03-фикса аллокаций в горячем пути, каркас ExploreByTouchHelper (Kotlin, androidx.customview) с жёстким APK-гейтом.

**User story:** As a татароязычный пользователь на бюджетном телефоне, я вижу привычную «айфоновскую» клавиатуру — светлую днём, тёмную ночью, без лагов и GC-пауз при печати — и весь ввод фаз 2–5 работает как раньше.

**Красная линия:** НЕ переписывать KeyboardView/MainKeyboardView-рендер, НЕ оверрайдить onDraw, НЕ снимать `final` с MainKeyboardView, НЕ трогать PointerTracker/InputLogic/механику фаз 2–5. Java-граница: KeyboardTheme.java + точечные PERF-фиксы в KeyboardView.java/MainKeyboardView.java + a11y-wiring в MainKeyboardView.java + один новый Kotlin-файл. Compose запрещён. Ассеты Apple (SF Pro, SF Symbols) запрещены — path'ы иконок ТОЛЬКО собственные/Material Symbols (Apache-2.0). Boundary — механический diff-чек от e0d470b (Verification п.5).

- Источник правды: `.planning/phases/06-ios-skin-canvas/06-RESEARCH.md` (аудит рендера по file:line, вердикт «переписка НЕ нужна») + `06-CONTEXT.md` (палитра/геометрия LOCKED).

- **PERF-03** (research §6): горячий путь почти чистый; ровно 3 аллокации — (1) iterator в цикле onDrawKeyboard (KeyboardView.java:280), (2) `new KeyDrawParams(this)` в mayCloneAndUpdateParams на каждый ключ с attrs (KeyDrawParams.java:126), (3) строка языка на каждую отрисовку пробела (MainKeyboardView.layoutLanguageOnSpacebar:558-576). - **ExploreByTouchHelper** (research §4): в исходниках отсутствует; живёт в `androidx.customview:customview` (~150–250 КБ в release с R8; `dependencies {}` в build.gradle сейчас ПУСТ — первая внешняя зависимость проекта). Hover-события не пересекаются с PointerTracker (touch-путь не изменён) — риск регрессий нулевой. **HARD GATE:** замер APK до/после; при превышении бюджета 3 МБ или транзитивном bloat — фолбэк: откатить зависимость+каркас, отложить в фазу 9 с записью в STATE.md.

- Риски ресерча §7 держать в голове при исполнении: R2 (иконки общие для всех 7 тем — менять форму path, НЕ механизм тонировки `?attr/functionalTextColor`), R3 (live-reload на SDK ≥ S — если тема не подхватывается, снять условие `< S` в KeyboardSwitcher.java:91-93, 1 строка), R6 (dev-prefs могут хранить старую тему — учесть в UAT).
