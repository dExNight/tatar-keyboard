# Plan 02-01 — Татарская раскладка: XML-данные + регистрация tt + MVP-активация (wave 1)

**Goal:** На устройстве печатается татарский текст: вся ЙЦУКЕН + видимый пятый ряд `ә ө ү җ ң һ` сверху, тапом (LAYOUT-01); слои `?123`/`#+=` открываются и возвращают к буквам (LAYOUT-04); раскладка целиком описана XML-файлами по паттерну east_slavic — следующая раскладка (латиница Zamanälif) добавляется файлами без правки движка (LAYOUT-05).

**User story:** As a татароязычный пользователь, I want открыть клавиатуру и напечатать «әни, өй, үрдәк, җир, таң, һава» обычными тапами, so that татарский — первым классом, без long-press-акробатики.

Vertical-slice дисциплина: Tasks 1–2 — чистые данные (раскладка существует и компилируется); Task 3 делает её выбираемой; Task 4 — активной по умолчанию; Task 5 — on-device чекпойнт. Ни одна задача не оставляет проект несобираемым.

## Context

- Источник правды: `.planning/phases/02-tatarskaya-raskladka/02-RESEARCH.md` (все пути и номера строк проверены по коду форка) + locked decisions из `02-CONTEXT.md`: пятый ряд **алфавитный** `ә ө ү җ ң һ`, **сверху** над `й ц у к е н…`, **без** постоянного цифрового ряда (цифры в `?123`; опция showNumberRow должна продолжать работать).
- Прямой образец — цепочка east_slavic: `keyboard_layout_set_east_slavic.xml` → `kbd_east_slavic.xml` (`<switch>` по showNumberRow) → `rows_east_slavic.xml` → `rowkeys_east_slavic1–3.xml`. Резолвинг layout set — по имени в рантайме (`KeyboardLayoutSet.Builder.getXmlId` через `getIdentifier`), поэтому сами XML подхватываются без Java.
- Решения открытых вопросов ресерча (приняты рекомендованные): **Q1** — свои `rowkeys_tatar1–3` с литеральными кодпоинтами (не reuse east_slavic → не трогаем `KeyboardTextsTable.java` вообще); **Q2** — locale-строка `"tt"` для MVP (`tt_RU` — фаза 3 вместе с тремя subtype); **Q3** — MVP-активация через `getDefaultSubtypes` (tt первым) — минимальный механизм, в том же файле-реестре.
- **Зафиксированное отклонение от «раскладки = данные, ноль Java»** (CLAUDE.md hard constraint, допуск из CONTEXT «Claude's Discretion»): форк хранит реестр выбираемых locale жёстко в `SubtypeLocaleUtils.java` (`sSupportedLocales[]` + `switch(mLocale)` в `SubtypeBuilder.getSubtypes()`); раскладка вне реестра невыбираема и не восстанавливается из prefs (`getSubtype` → null). Правки — только записи-в-реестр в ОДНОМ файле (константа locale, константа layout, `case` c `break`, вставка в default-список): движок парсинга/отрисовки не затрагивается, сама раскладка — чистые XML-данные. Гипотеза CONTEXT про «subtype в method.xml» опровергнута ресерчем — method.xml для выбора раскладки в этом форке не работает, его не трогаем.
- Анти-паттерны (не делать): править `method.xml`; трогать `KeyboardTextsTable.java` (не нужно при литеральных rowkeys); добавлять moreKeys/long-press дубли (LAYOUT-02 — фаза 3); ru/en раскладки, глобус (фаза 3); визуальная полировка под iOS (фазы 6–7); конвертация Java→Kotlin.

## Flagged assumptions

- **A1 (высота, MEDIUM):** `16.667%p` для 6 рядов и `20%p` для 5 подобраны расчётно (сумма = 100% baseHeight) на готовых 5row-фракциях; точная посадка на реальных экранах верифицируется только Task 5 (logcat «too tall» + глаза). Если нижний ряд всё же подожмётся — подбор фракций в тех же XML-атрибутах, без Java (уменьшенная высота пятого ряда ~0.75–0.8 — отложенная iOS-полировка фаз 6–7, здесь не делаем).
- **A3 (регистр):** заглавные Ә Ө Ү Җ Ң Һ — штатный `toUpperCase(Locale("tt"))`; Unicode-пары определены, но runtime-подтверждение — Task 5 п.4.
- **Locale `"tt"` без `_RU`:** display name в настройках может быть неполным (LocaleResourceUtils) — приемлемо для MVP; `tt_RU` и три subtype — фаза 3 (SWITCH-01). Если фаза 3 сменит строку на `tt_RU`, prefs-миграция тривиальна (дефолты пересоздаются при невалидной записи).
- **Устройство может быть недоступно** (как в фазе 1): Task 5 тогда откладывается в STATE.md Blockers с точным чек-листом — BUILD-критерии фазы (сборка, aapt2, diff-границы) при этом полностью закрыты автоматикой.
