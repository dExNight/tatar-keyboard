# Plan 04-01 — Механика ввода: тонкая верификация (регистр, автокапс, backspace, Enter) (wave 1)

**Goal:** Доказать без единой правки кода, что INPUT-01..04 уже работают в базе форка и корректно подхватываются нашими раскладками tatar/russian — вердикт ресерча 04-RESEARCH.md: **ALL WORKS, gap list пуст**. Работа фазы = (1) структурная верификация, пиновая доказательства ресерча fail-capable-проверками, (2) bookkeeping принятых трактовок в REQUIREMENTS.md/STATE.md, (3) on-device UAT-чекпойнт по стандартной отложенной схеме.

**User story:** As a татароязычный пользователь, I want shift/caps-lock с заглавными Ә Ө Ү Җ Ң Һ, автокапитализацию по типу поля, backspace, удаляющий ә целиком и разгоняющийся при удержании, и Enter, выполняющий действие поля, so that символьный ввод ощущается как в Gboard — на любой раскладке, офлайн.

**ZERO-CODE фаза.** Красная линия контекста («не переписывать работающую механику») в пределе: механика уже есть → диф кода этой фазы обязан быть **пустым**. Это не пожелание, а механический boundary-check плана (Verification п.4).

## Context

- Источник правды: `.planning/phases/04-mekhanika-vvoda-registr/04-RESEARCH.md` (аудит по file:line, все четыре вердикта WORKS) + `04-CONTEXT.md`. Ключевые цепочки: shift-стейт-машина `KeyboardState.java` (двойной тап через системный `ViewConfiguration.getDoubleTapTimeout()`, лейблы апкейсятся по elementId — `Key.needsToUpcase` → `toUpperCase(locale)`, у всех букв пятого ряда штатные Unicode-пары ә↔Ә ө↔Ө ү↔Ү җ↔Җ ң↔Ң һ↔Һ); автокапс `getCursorCapsMode` → `CapsModeUtils.getCapsMode` (маскируется InputType — email/URL off), `layoutUsesAutoCaps` не содержит tatar/russian → true; backspace `numChars = supplementary ? 2 : 1` → `deleteSurroundingText`, автоповтор 400 мс → 50 мс через `isRepeatable` + `TimerHandler`; Enter — XML-switch по `imeAction` в `key_styles_enter.xml` + `performEditorAction` в `InputLogic`, `IME_FLAG_NO_ENTER_ACTION` → newline.
- **USER DECISION (2026-07-18), зафиксировано:** трактовка INPUT-03 **принята** — подсчёт chars по кодпоинту + `deleteSurroundingText(numChars, 0)` = семантический эквивалент `deleteSurroundingTextInCodePoints` (суррогатная пара удаляется целиком; менять API не нужно — вокруг синхронный кэш `mTextBeforeCursor`); «ускоряется при удержании» = схема AOSP-автоповтора (задержка 400 мс → серия 50 мс, ~20 удалений/сек). Прогрессивный разгон (удаление словами, как в Gboard) — **backlog post-MVP**, не пробел фазы (`repeatCount` уже пробрасывается в `onKeyRepeat` — достраивается тривиально при желании после юзер-теста).
- Бонус сверх INPUT-01 (фиксируем в аннотации): caps lock доступен также long-press'ом shift (`!code/key_capslock`, `config_longpress_shift_lock_timeout = 1200` мс).
- Фолбэк shifted-элементов штатный: наши layout set'ы объявляют только `alphabet` (как upstream qwerty) — `KeyboardLayoutSet` берёт параметры от ELEMENT_ALPHABET, но `KeyboardId` несёт фактический shifted-elementId → `needsToUpcase` срабатывает. **Ничего добавлять не нужно** — соблазн «дописать alphabetManualShifted-элементы для надёжности» = анти-паттерн.
- Прецедент формата: план 03-01 (fail-capable verify, отложенный UAT-чекпойнт, механические diff-границы). Прецедент простановки: галочки требований в REQUIREMENTS.md чек-боксами НЕ ставим до UAT — обновляем только Traceability-статус и аннотации (фаза 3 закрылась «complete-local», LAYOUT/SWITCH-галочки проставлены при verify-work; здесь то же: финальная простановка — после verify-work/UAT).
