# Plan 01-01 — Форк, applicationId, Kotlin interop (walking skeleton, wave 1)

**Goal:** Форк Simple Keyboard живёт в этом репозитории, собирается под `org.tatarkeyboard.ime`, печатает на устройстве рядом с оригиналом, Kotlin-код доказуемо участвует в сборке.

**User story:** As a татароязычный пользователь, I want установить форк-клавиатуру и печатать ею в реальном приложении, so that фундамент IME доказан end-to-end на устройстве.

Vertical-slice дисциплина: уже после Task 1 приложением можно пользоваться (сток печатает); Task 3 делает его различимым и сосуществующим с оригиналом; Task 4 добавляет interop без изменения поведения. Ни одна задача не оставляет проект несобираемым.

## Flagged assumptions

- Side-by-side критерий (SC-2) полноценно проверяется только если на устройстве установлен и оригинальный Simple Keyboard; если пользователь не может его поставить, уникальность applicationId доказывается `aapt2 dump badging` (package ≠ `rkr.simplekeyboard.inputmethod`) — считаем это достаточным, конфликт установки при разных package невозможен by construction.
- compileSdk/targetSdk остаются 37 (база), вопреки «36» в CLAUDE.md — отклонение зафиксировано в SKELETON.md; CLAUDE.md обновить отдельным коммитом вне этой фазы.

## Prohibition recall (spec-less fallback, две стадии — запись для фазы)

Stage 1 (adversarial, over-produce) по PERF-04 и границам фазы: INTERNET через зависимость/тулинг; аналитика/Firebase; Apple-ассеты; срыв Apache-2.0 (удаление LICENSE/заголовков); коммит keystore/паролей; ослабление CI-проверки до grep-only; телеметрия побочными каналами; переименование пакетов «для чистоты»; даунгрейд тулчейна; смена поведения стока.

Stage 2 (precision) — kept (values/legal/privacy, бесспорно бесspoke): (1) Apache-2.0 гигиена форка → authored здесь; (2) запрет Apple-ассетов → authored здесь; (3) запрет аналитики/телеметрии/сторонних сетевых SDK → authored в plan 01-02 (там появляется поверхность зависимостей/CI). Итого 3 kept = 3 authored, 0 silent drops.

Canon-referral drops (breadcrumb, не минтим): «keystore/пароли в git» — каноничная секрет-гигиена, закрыта threat model T1 плана 01-02 + .gitignore-критериями; «grep-only CI» — routine engineering качества проверки, закрыто явной PERF-04 truth в plan 01-02. Сам запрет INTERNET не минтится прохибишном — он authored как PERF-04 truth + негативный CI-тест (plan 01-02).
