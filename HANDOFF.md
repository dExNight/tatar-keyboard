## Что решено по ходу и почему

**Тест `TapReproTest.tappingAWordTheStripIsPaintingAlwaysReachesTheEditor` помечен
`@Ignore`.** Он про второй, независимый дефект полосы (`SuggestionsController.kt:1186-1188`:
кандидаты отвязываются, полоса не перерисовывается). Закрывать его — выбор между двумя
вариантами UX, и это решение оператора, а не правка. Вопрос отправлен ему в
`.smgr/tt-version-1.8.1/ask.json` (варианты A/B/C, рекомендация B на 1.8.1), помечен как
**не блокирующий** — сборка от ответа не зависит. Снять `@Ignore` — одна строка;
комментарий у аннотации объясняет, когда.

**Из changelog убрано утверждение про зажатый backspace.** `docs/TAP-REPRO.md` выводил из
кода третье следствие — порчу текста справа от курсора при автоповторе. Проверено на
эмуляторе на 1.8.0 двумя способами (удержание 1,2 с; два быстрых нажатия, три повтора) —
**не воспроизвелось ни разу**, оба плеча дали одинаковый правильный результат. Обещать
пользователю починку того, чего никто не видел, нельзя; правка путь всё равно закрывает.
Разбор — в отчёте, раздел «Третье следствие».

**Freeze-коммит amend-нут один раз** — ровно ради этой правки формулировки в `CHANGELOG.md`,
до написания отчёта, и дерево пересобрано целиком. Поэтому все числа отчёта относятся к
`46f3b3a`, а не к первой сборке. Побочный факт, полезный следующему: две сборки одного
дерева, различающиеся только текстом `CHANGELOG.md` (в APK не входит), дали APK одного
размера с разными SHA-256 — **сборка не байт-в-байт воспроизводима, это подтверждено
прямым опытом.**

* **Досье этой миссии пришло пустым** (ЦЕЛЬ и ГОТОВО КОГДА не заданы). Работа велась по

* **`FakeEngine` в `SuggestionsControllerTest` слеп к дефектам этого класса** (одна
  константа `TOKEN`, `isCurrent()` всегда `true`). Для всего, что связано с выброшенными
  результатами и сменой поколения, брать `LatestOnlyEngine` из `TapReproTest`.
* **Эмулятор годится для A/B симптомов гораздо лучше, чем кажется.** Состояние поля читать
  не по скриншоту, а из `uiautomator dump` — там реальный текст `EditText`. Два нажатия,
  между которыми нельзя дать системе вздохнуть, посылать одной командой:
  `adb shell 'input tap X1 Y1; input tap X2 Y2'`; через два отдельных вызова окно уже
  закрывается.
* **Окна короче ~50 мс через `adb input` не ловятся** — на этом сорвалась проверка третьего
  следствия. Если понадобится, это уже инструментальный тест или временная диагностика в
  logcat.
* Эмулятор `tatar_e5_test` остался запущен, на нём установлена 1.8.1, `adb root` включён.
