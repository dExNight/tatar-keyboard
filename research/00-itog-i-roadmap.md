# Итог ресерча и roadmap проекта «Татарская клавиатура»

Дата: 18.07.2026. Главный документ проекта: сводит выводы всех секций ресерча, разрешает противоречия между ними и фиксирует принятые решения. Самодостаточен — читается без остальных файлов; за деталями и источниками см. секции по оглавлению.

Проект: нативная Android-клавиатура (IME) с татарской кириллической раскладкой (ә ө ү җ ң һ), визуально в стиле системной клавиатуры iOS, максимально лёгкая и отзывчивая на бюджетных устройствах. Разработчик — новичок в Android.

## 2. Рекомендуемый стек и архитектура

**Стек (консенсус всех секций, противоречий нет):**

- **Язык:** Kotlin для всего нового кода (официальная рекомендация Google; с AGP 9.0 поддержка Kotlin встроена в плагин). Java-код форкаемой базы не конвертируем — interop бесплатный, точечная конвертация только при существенной переписке файла (06, дополнение б).
- **UI:** классический **кастомный `View` + Canvas** — один View на всю клавиатуру, клавиши рисуются в `onDraw`. Так устроены AOSP LatinIME, HeliBoard, Gboard. **Jetpack Compose в IME-процессе — нет**: unbundled-библиотека без Zygote-прогрева, +20–40 МБ RAM и медленный холодный старт — дисквалификация для бюджетных устройств (01 §1, 02 §1). Compose допустим только в companion-приложении настроек (и то спорно из-за размера APK).
- **Flutter/React Native — непригодны** в принципе: у IME нет Activity, `onCreateInputView()` обязан вернуть нативный View, Dart VM/Hermes добавляют 100–200+ МБ RAM.
- **NDK/C++ — не нужен** на старте. Предикшен v1 — на Kotlin (префиксный поиск + Дамерау–Левенштейн по частотному словарю).
- **Инструменты:** Android Studio Quail (2026.1.x), AGP 9.x, Gradle 8.14+/9.x, Kotlin 2.3+; `minSdk 24–26`, `targetSdk/compileSdk 36`.
- **Без разрешения INTERNET** — вообще (проверяемая ОС гарантия приватности, маркетинговое преимущество, упрощает Data Safety до «No data collected»).

**Архитектура IME:**

```
TatarImeService : InputMethodService        // directBootAware=true
 └─ onCreateInputView() → InputViewContainer (FrameLayout, insets-паддинг для API 35+)
     ├─ KeyboardView : View                  // Canvas: клавиши, подсветка, превью
     │   ├─ KeyboardLayout                   // модель: List<Row<Key>>, доли ширины; данные (JSON/Kotlin), не XML
     │   ├─ PointerTracker[N]                // multi-touch, таймеры long-press/repeat
     │   ├─ KeyPreviewDrawer                 // баллон в том же слое (не PopupWindow)
     │   ├─ PopupPanelDrawer                 // long-press альтернативы, slide-to-select
     │   └─ KeyboardAccessibilityDelegate    // ExploreByTouchHelper: клавиши = виртуальные узлы
     └─ KeyboardTheme                        // light/dark, iOS-палитра, все цвета в коде
```

Ключевые системные решения (01): три subtype в `method.xml` (`tt_RU`, `ru`, `en_US`), глобус через `switchToNextInputMethod`, `onEvaluateFullscreenMode() = false` (как iOS, без extract mode), честная обработка password-полей (никаких подсказок/обучения), `deleteSurroundingTextInCodePoints` для backspace, всё тяжёлое — асинхронно после первого кадра.

## 3. Решение «форк vs с нуля»

**Однозначная рекомендация: форк Simple Keyboard (rkkr).** Это сведённый вердикт из 06 («Дополнение» — единственный источник правды; ранние расхождения между 01/06/07 там сняты).

Почему не с нуля: «своё IME в 1–2 тыс. строк» — это и есть Simple Keyboard, уже написанный и оттестированный (AOSP LatinIME с вырезанным словарным движком). С нуля — 2–4 месяца работы новичка только до уровня «стабильно печатает», при этом всё равно с подглядыванием в те же исходники.

Почему именно Simple Keyboard:
1. **Лёгкость** — главный приоритет проекта: APK ~0.65 МБ, ноль нативных либ, минимум зависимостей. Единственная база, гарантированно «летающая» на бюджетниках.
2. **Apache-2.0** — полная свобода лицензирования в будущем (в отличие от GPL-3.0 у HeliBoard).
3. **Посильна новичку**: один модуль, ~400 коммитов, знакомый AOSP-скелет — реально прочитать целиком. Лучший «учебник по IME».
4. Татарская раскладка добавляется правкой XML — день работы.
5. Живой проект (релиз 6.4, май 2026).

Последствия: наш форк — Apache-2.0, обязателен **уникальный `applicationId`**; предикшена в базе нет — в v1 пишем свой простой (это осознанная цена). **Порт AOSP-движка словарей в Simple Keyboard — не путь апгрейда**: доисследование в 06 показало, что это ~300 файлов C++ + 40+ Java-классов без прецедентов чистого выдирания.

**План Б — форк HeliBoard** (GPL-3.0): если после прототипа станет ясно, что AOSP-автокоррекция нужна с первой версии. Цена: GPL на весь продукт (закрытая монетизация исключена), ~20 МБ APK, C++, большая кодовая база. Контрольная точка для ветвления: прототип раскладки в установленном HeliBoard (добавляется из настроек без кода!) + 1–2 недели личного использования; решение принять **до** больших вложений в iOS-скин.

Не берём: FlorisBoard (beta, Compose тяжёл, предикшена нет), AnySoftKeyboard (15 лет легаси), Fossify (GPL без преимуществ), AOSP LatinIME напрямую (сборка AOSP, maintenance mode).

## 4. Ключевые решения по татарской раскладке

**Принятое решение проекта (зафиксировано в 05 §4.5 и 07 «Дополнение»):**

```
[доп. ряд]   ә  ө  ү  җ  ң  һ           ← 6 клавиш, высота ~0.75–0.8 буквенного ряда
[ряд 1]      й ц у к е н г ш щ з х      ← 11 клавиш
[ряд 2]      ф ы в а п р о л д ж э      ← 11 клавиш
[ряд 3]      ⇧ я ч с м и т ь б ю ⌫
[ряд 4]      123  🌐  пробел  ⏎
```

- **Доп. буквы — отдельным пятым рядом, не long-press-only.** Обоснование: ә — 5-я по частоте буква языка (6.65%), суммарно 6 доп. букв = 10.6% всех буквоупотреблений; long-press (~300–500 мс) на каждой ~9-й букве неприемлем. Прецедент — казахское сообщество HeliBoard (issue #2130) с теми же буквами: «long-press popups slow down typing significantly».
- **Long-press дублирует** доп. буквы на базовых клавишах (а→ә, о→ө, у→ү, н→ң, ж→җ, х→һ, э→ә, г→һ) — два пути к одной букве.
- Порядок ряда — алфавитно-мнемонический `ә ө ү җ ң һ` (легче искать глазами); вариант по частоте — на юзер-тест позже.
- **Русская раскладка** — стандартная ЙЦУКЕН + те же long-press на татарские буквы (вставить татарское слово без переключения). **Английская** — QWERTY. Три subtype: tt_RU / ru / en_US.
- **Билингвальный ввод (v1):** tt-subtype несёт два словаря — tt главный + ru secondary с понижающим весом по confidence (схема HeliBoard `DictionaryFacilitator`, открытый референс). Не новый subtype «tt+ru», не смешанный словарь. Fuzzy-замены суррогатов (э→ә, у→ү: «эйбэт»→«әйбәт») — только при поиске в татарском словаре.
- Геометрия проверена на худшем экране 320dp: буквенная клавиша ~25dp (уровень ЙЦУКЕН в Gboard и iPhone SE), клавиши доп. ряда ~48dp. В v1 строка подсказок **стекируется над** доп. рядом (не заменяет его — ә/ө нужны в середине слова, когда подсказки активны).
- Опции в настройках (не MVP): «компактный режим» (без доп. ряда), «Windows-раскладка» для старой школы ПК.
- **Латиница — не в MVP** (кириллица — официальная графика с 2012; латиница — нишевой сценарий диаспоры). Раскладка = данные, не код, так что добавить позже дёшево.
- Unicode: все 6 букв — обычные BMP-кодпоинты кириллического блока, покрыты Roboto на любом Android — проблем с отображением и `commitText` нет. Сортировка словаря — `android.icu.text.Collator` для локали `tt` (алфавитный порядок закона РТ обычный compareTo не даёт).

Ниша против конкурентов: у Gboard/SwiftKey/Яндекса татарский — «язык второго сорта» через long-press; ttkeyboard устарел визуально; Тиз.Яз громоздок. Свободная ниша: «татарский первым классом + красивая + лёгкая на бюджетнике + офлайн», плюс дистрибуция в RuStore, где Gboard нет.

## 5. Границы «стиля iOS»

**Воспроизводим (низкий юридический риск — функциональные, общеотраслевые паттерны):**

- Геометрия: высота ~216dp (4 ряда) как доля экрана (~35%, с настройкой), радиус клавиш ~5dp, зазоры 6dp (ужимаем до 4–5dp при 11 клавишах), резкая тень 1dp вниз без blur (не Material elevation!).
- Палитра (снята с реальной iOS через KeyboardKit): светлая — фон #D4D6DD, клавиши #FFFFFF, служебные #B3B7C0; тёмная — фон #2C2C2C, клавиши #6B6B6B, служебные #474747 (непрозрачные — blur iOS на слабых устройствах не воспроизводим и не надо).
- Баллон-попап над клавишей (мгновенный, без анимации), long-press-панель с выбором скольжением, три состояния Shift (off / shift / caps-lock двойным тапом, регистр букв на клавишах меняется), Enter с подписью действия, автоповтор backspace, свайп по пробелу = курсор.
- «Отзывчивость без анимаций»: реакция на `ACTION_DOWN`, никакого ripple, никаких ObjectAnimator.
- Звук/хаптика — системные Android (`playSoundEffect(FX_KEYPRESS_*)`, `performHapticFeedback(KEYBOARD_TAP)`), свои mp3 не нужны.

**Нельзя (реальный риск):**

- **Шрифт SF Pro / SF Symbols в APK — жёсткий запрет** лицензии Apple (только мокапы для Apple-платформ, встраивание в ПО запрещено). Замена: **`Typeface.DEFAULT` (Roboto)** — 0 байт в APK, гарантированная кириллица включая ә ө ү җ ң һ; опционально Inter (SIL OFL) как более близкий аналог SF ценой ~50–300 КБ.
- Пиксель-в-пиксель копии ассетов Apple (иконки из iOS, звуки клика) — копирайт на произведения, работает независимо от trade dress. Иконки shift/глобус/backspace рисуем сами (VectorDrawable) или Material Symbols.
- Маркетинг со словами «iOS/iPhone-клавиатура», яблоко в иконке — товарные знаки + отклонение в Play за impersonation. Формулировка «минималистичный светлый стиль» — ок.

Trade dress сам по себе — слабый риск: в Apple v. Samsung суд признал UI-элементы функциональными и не подлежащими trade-dress-защите; Gboard/SwiftKey годами выглядят близко к iOS без исков.

## 6. Бюджеты производительности (из 03 §9)

| Метрика | Цель | Инструмент проверки |
|---|---|---|
| PSS показанной клавиатуры | ≤ 30 МБ | `dumpsys meminfo` |
| PSS в фоне (30 с после скрытия) | ≤ 15–20 МБ | `dumpsys meminfo` |
| Холодный старт до показа (бюджетное устройство) | < 400 мс | Perfetto + Trace-маркеры |
| Тёплый показ | < 150 мс | то же |
| Обработка касания (наш код) | < 5 мс | `eventTime` vs `commitText` |
| Janky-кадры при печати | ~0% | `gfxinfo` / JankStats |
| `onDraw` на слабом SoC | < 4–5 мс | GPU Profiler |
| APK (release, per-ABI / без native) | 1–3 МБ | APK Analyzer |
| GC-события во время печати | 0 | logcat / Memory Profiler |
| minSdk | 24–26 | — |

Главные правила достижения: ноль аллокаций в `onDraw`/`onTouchEvent` (все Paint/Rect — поля), точечный `invalidate(rect)`, `onTrimMemory` + отложенный сброс кэшей после скрытия, ленивая инициализация всего после первого кадра, Baseline Profile (+25–40% к холодному старту именно на слабых устройствах), ветка `isLowRamDevice()` для отключения эффектов, никаких Firebase/Analytics в процессе. Холодный старт — главная метрика, а не редкий случай: на 1–2 ГБ устройствах LMK убивает скрытую клавиатуру регулярно.

## 7. Roadmap

### Этап 0 — окружение и прототип (1–2 недели)

1. Установить Android Studio Quail, SDK 36, эмуляторы API 26 и 35+; завести Git-репозиторий (open-source, Apache-2.0).
2. **Прототип раскладки без единой строки кода:** установить HeliBoard и добавить татарскую раскладку текстовым файлом через Settings → Layouts; 1–2 недели личного использования — отладить эргономику пятого ряда и long-press и заодно ответить на вопрос «жить ли без автокоррекции» (контрольная точка форк-решения из §3).
3. Hello-world IME: форкнуть Simple Keyboard, собрать, установить, включить через системные настройки, убедиться, что печатает. Прочитать кодовую базу (это учебник).
4. Настроить keystore (один ключ на RuStore/F-Droid/GitHub, upload key для Play), `tools:node="remove"` на INTERNET + CI-проверка permissions.

### MVP (4–8 недель) — «клавиатура, которой реально пользуешься вместо Gboard»

1. Раскладки: татарская (ЙЦУКЕН + пятый ряд `ә ө ү җ ң һ` + long-press дубли), русская (+ long-press на тат. буквы), английская, слои `?123` / `#+=`. Раскладки — данными.
2. Subtypes tt/ru/en, глобус (тап = цикл, long-press = системный пикер), `directBootAware`, `onEvaluateFullscreenMode() = false`.
3. Ввод: shift/caps-lock/автокапитализация, backspace с автоповтором (по кодпоинтам!), Enter по `imeOptions`, двойной пробел = точка, свайп по пробелу = курсор, multi-touch (коммит первой клавиши при втором касании).
4. iOS-скин: Canvas-отрисовка по палитре §5, light/dark по системе, баллон-превью и long-press-панель в собственном оверлее, хаптика/звук на `ACTION_DOWN`.
5. Доступность: ExploreByTouchHelper (клавиши = виртуальные узлы), `a11yLabel` с русскими описаниями тат. букв («татарская э» и т.п.), высота ряда ≥48dp. Закладывается сейчас — прикручивать потом больно.
6. Edge-to-edge (API 35+), инсеты, ландшафт, password-поля (без обучения/подсказок).
7. Тесты: Robolectric + ShadowInputMethodService (паттерн HeliBoard), ручная матрица: Telegram, Chrome/WebView, WhatsApp, пароли, поворот — на MIUI/HyperOS и One UI обязательно.
8. Параллельно (не блокирует): письмо в «Туган тел» о частотном списке, сборка v0-словаря из ttwiki + Leipzig с фильтром apertium-tat.
9. Онбординг-приложение: два шага «Включить»/«Выбрать», privacy policy на GitHub Pages (ru/tt/en).
10. Релиз MVP: GitHub Releases + IzzyOnDroid (сразу) → RuStore (модерация ~сутки) → Play closed testing (12 тестеров × 14 дней из татарского сообщества — заодно фидбек по раскладке; закладывать месяц до production).

### v1 — «умная» версия

1. Строка подсказок (стек над пятым рядом) + автокоррекция: свой движок — частотный словарь, префиксный поиск + Дамерау–Левенштейн ≤2 с учётом соседних клавиш; <5 мс на запрос.
2. Татарский словарь 150–250 тыс. словоформ (ttwiki + Leipzig, фильтр apertium-tat, частоты 0–255 логарифмически); русский/английский — из aosp-dictionaries (experimental-версии под CC BY 4.0, усечённые по частоте).
3. Билингвальный режим tt+ru (два словаря с весами по confidence, §4); автокоррекция суррогатов э→ә и т.д.; консервативный порог автозамены в смешанном тексте.
4. Заучивание пользовательских слов (уважать `IME_FLAG_NO_PERSONALIZED_LEARNING` и пароли).
5. Эмодзи-панель, история буфера обмена, настройки (высота, звук/вибро, компактный режим, автокоррекция вкл/выкл).
6. Baseline Profile + Macrobenchmark-замеры; инструментальные автотесты на эмуляторе в CI; Accessibility Scanner.
7. F-Droid: MR в fdroiddata, по возможности reproducible build (решить до первой публикации!).
8. Контрибьютить татарский словарь в HeliBoard/aosp-dictionaries — проверка качества + видимость проекта.

### Дальше («потом»)

- Next-word prediction (биграммы), морфологический предикшен для агглютинативных форм (исследовательская задача).
- «Windows-раскладка» как опция, латиница (по таблице транслитерации 2012 г.), планшетные режимы (float/split).
- Голосовой ввод — только после проверки поддержки tt системным распознаванием (не подтверждена).
- Свайп-ввод — честно: открытой реализации нет (в HeliBoard — закрытая Google-либа), своя — годы работы. Не обещать пользователям.

## 8. Главные риски и открытые вопросы

**Риски:**

1. **Без автокоррекции MVP может «не зайти»** — пользователи избалованы Gboard. Митигация: контрольная точка после прототипа (этап 0, п. 2); если без предикшена неюзабельно — миграция на форк HeliBoard **до** больших вложений в iOS-скин (тогда продукт становится GPL-3.0).
2. **Лицензия данных «Туган тел» не определена** (публичной выгрузки нет) — не блокер: fallback ttwiki (CC BY-SA) + Leipzig; лицензии Leipzig проверять покорпусно; стабильный ru-словарь AOSP — с неподтверждённой лицензией источника, предпочесть experimental (CC BY 4.0).
3. **Качество словаря при агглютинативности**: словарь словоформ покрывает татарский хуже, чем английский; 150–250 тыс. форм закрывают быт, но ожидания калибровать.
4. **OEM-прошивки (MIUI/HyperOS)** — многолетний баг «исчезающей клавиатуры», агрессивные киллеры → постоянные холодные старты. Митигация: бюджеты §6, обязательное физическое Xiaomi-устройство в тестовом парке, шаблон bug report с полем «приложение + текстовое поле + прошивка».
5. **Зоопарк InputConnection** (WebView шлёт keyCode 229, Compose TextField, кастомные редакторы банков) — главный источник багов IME вообще. Митигация: в MVP не использовать composing-текст (коммитить сразу), удаление через `deleteSurroundingText`, матрица тестирования из 03 §10.
6. **Play для нового личного аккаунта**: 12 тестеров × 14 дней + ревью — плюс месяц к релизу; RuStore/IzzyOnDroid позволяют выйти раньше.
7. **Юридика стиля**: риск только при нарушении границ §5 (шрифт/ассеты/маркетинг Apple); сама геометрия и палитра безопасны.
8. **Соло-разработчик-новичок**: главная защита — маленькая посильная база (Simple Keyboard), отказ от свайпа/голоса/своего C++, готовые паттерны из LatinIME/HeliBoard как справочник.

**Открытые вопросы:**

- Точная планка targetSdk для новых приложений после 31.08.2026 (35 или 36) — сверить с таблицей Play Console при сабмите.
- Поддержка татарского в системном SpeechRecognizer — проверить на устройстве до обещаний голосового ввода.
- Условия регистрации физлица в RuStore (процедуры менялись) и объём обязательной русской локализации UI по закону с 01.03.2026.
- Ответ «Туган тел» по частотным данным; финальные формулировки a11y-описаний тат. букв — согласовать с сообществом незрячих татароязычных пользователей.
- Порядок клавиш пятого ряда (алфавитный vs частотный) — юзер-тест после MVP.
- minSdk 24 vs 26 — решить по факту аналитики региона (доля API 24–25 <1% → брать 26).
